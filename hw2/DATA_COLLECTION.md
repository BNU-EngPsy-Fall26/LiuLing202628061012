# 正式收数操作清单

> 目标：≥5 名其他参与者，每人完成两个实验；保证数据可分析、可追溯。

---

## 一、收数前（一次性）

- [ ] 参数已冻结（见 `CALIBRATION.md` 冻结记录）
- [ ] `README.md` 的预注册部分已提交（含预测与修订记录）
- [ ] 清空 `/hw2` 中的 `test_search` / `test_route_change`
- [ ] 确认网页使用**正式模式**（网址**不带** `?test=1`）
- [ ] 用一个新编号完整跑一遍，确认上传成功、无 `warnings`
- [ ] 记录当前时间与 commit 号：__________

---

两名实验的任务顺序需要平衡。按下表分配（奇数先任务一，偶数先任务二）：

| 编号 | 先做 | 备注 |
| --- | --- | --- |

| P05 | 任务一 | |
| P06 | 任务二 | |
| P07 | 任务一 | |

要求：

- [ ] 每名被试**只用一个编号**，两个实验共用
- [ ] 编号不含姓名、学号、手机号
- [ ] 同一人不要重复提交多份

---

## 三、每名被试开始前（口头说明）

1. 这是课程作业实验，不是考试，没有对错压力
2. 全程约 15–20 分钟，中途可以休息
3. 实验一：看到黄色船按 F，只有蓝船/礁石按 J
4. 实验二：发现哪艘船移动了，先按空格，再点那艘船
5. 请关闭聊天软件通知，尽量在安静环境
6. 数据匿名，只记录按键与点击

---

## 四、每名被试结束后（检查）

- [ ] 结束页显示「已保存 80 条」与「已保存 40 条」
- [ ] 点击「上传实验一/二数据」，出现「上传成功」
- [ ] 若出现 `warnings`，截图并记录，但不要当场修改代码
- [ ] 若上传失败，先下载 JSON 备份，再重试
- [ ] 在 `/hw2` 项目页确认人数 +1

---

## 五、收数期间（每天检查）

- [ ] 参与人数（实验一 / 实验二应相同）
- [ ] 每个实验的记录数是否为 80 / 40 的整数倍
- [ ] 是否有同一编号重复提交
- [ ] 是否有异常短的完成时间（<8 分钟，可能乱按）

---

## 六、收数结束

- [ ] 至少 5 名有效参与者（建议 6–8）
- [ ] 导出 CSV/JSON（用下载密钥，密钥不要进仓库）
- [ ] 检查每个条件试次数是否平衡
- [ ] 备份原始数据到本地私密位置
- [ ] 开始分析（见下）

---

## 七、分析清单

### 实验一

- [ ] 每名被试 8 个条件的正确率与正确 RT
- [ ] 4 条斜率：`(RT_24 − RT_8) / 16`
- [ ] 2×2 方差分析（搜索类型 × 颜色对比度）
- [ ] 交互效应：`(联合低 − 联合高) − (特征低 − 特征高)`
- [ ] 截距（区分 H4）
- [ ] 误报率（无目标试次按 F 的比例）

### 实验二

- [ ] 每名被试 4 个条件的中位发现时间
- [ ] 平均定位误差
- [ ] 描述性：发现率、超时率
- [ ] 2×2 方差分析（显示模式 × 变化位置）于中位时间
- [ ] 交互效应：`[(均匀 − 稳定)_边缘 − (均匀 − 稳定)_中央]`
- [ ] 与 Rensink（1997）对比：发现时间量级、漏检现象

### 共同

- [ ] 效应量：Cohen's dz
- [ ] bootstrap 95% 置信区间
- [ ] 个体数据点图
- [ ] 在 `results.html` 核对网页数字与 CSV 一致

## 八、常见问题

| 现象 | 处理 |
| --- | --- |
| 上传返回「项目码不存在」 | 检查 `js/upload.js` 中 `PROJECT_CODE` |
| 记录数不是 80/40 | 检查是否有试次被提前中断 |
| 同一人做了两遍 | 保留编号，但在分析中只取第一次完整数据，并记录 |
| 超时率过高 | 按 `CALIBRATION.md` 的事前规则调整并记录 |
| 中位时间过短（<1.5s） | 可能乱按，检查正确率与点击误差 |
