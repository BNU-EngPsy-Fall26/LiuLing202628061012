# 部署到自己的服务器 —— 完整手册（备案 + 域名 + HTTPS）

> ### 这是**备用**路线 —— 主路线是 Railway
>
> **默认走 [`部署步骤.md`](部署步骤.md)（Railway + 自己的域名）**：
> $5/月、免备案、一小时上线、带持久磁盘，够用。
>
> **什么时候才需要看这份**：学生每次开页面要等一秒多，你觉得不能忍，
> 想把服务器搬回国内 —— 那样访问快几十倍。
>
> **代价**：买服务器（一年几百块）+ **ICP 备案（1~20 个工作日）**
> + 自己管 nginx / HTTPS 证书 / 自动备份。
>
> **好处**：速度、以及数据 100% 在自己手里。
>
> **两条路用同一份代码**，所以随时可以搬过来，代码一个字都不用改。
>
> ---
> 这份手册假设你**能照着敲命令，但不懂为什么**。所有要复制的东西都放在灰框里，
> **一个字都别改**（改的地方我会特别标出来）。
> 政策类内容（尤其备案）**以你选的云厂商页面为准** —— 政策改得勤，
> 我这份只是让你知道「有哪些环节、大概多久、容易卡在哪」。

## 0. 先看全景：这条路线分五个阶段

知道自己走到哪一步，比知道每一步怎么做更重要。

| 阶段 | 做什么 | 大概多久 | 最容易卡在哪 |
|---|---|---|---|
| **A. 买** | 买域名、买服务器 | 1 天 | 无 |
| **B. 等实名** | 域名实名认证 | **1~3 天** | 认证信息必须和后面备案的人**一致** |
| **C. 备案** | 提交 ICP 备案，等管局审 | **1~20 个工作日** | ★ **个人备案的网站名称有禁忌词** |
| **D. 搭** | 拉代码、装服务、配 nginx | 半天 | 跟着第 5~8 步抄 |
| **E. 验** | 上线验收 + 配备份 | 1 小时 | 三条安全检查必须亲自验 |

**★ C 和 D 可以同时做。** 备案在等审核的时候，服务器你照样能连上去把服务搭好
（只是先别把域名解析过去）。所以别干等着。

**★ 这条路线有个大好处**：数据库就在服务器**你自己的这个硬盘**上
（`/var/lib/sdt/sdt.db`），**不依赖任何平台的磁盘功能、不看任何平台的脸色**。
你不用挂什么持久磁盘，第 5 步里那个 `SDT_DB_PATH` 只是为了把数据放在仓库外面
（方便备份、更新代码时不可能误伤），不是为了防丢。
**数据在不在，只取决于你这台机器。**

## 1. 先定四件事

| 定什么 | 建议 | 为什么 |
|---|---|---|
| **云厂商** | 阿里云 或 腾讯云，二选一 | 备案要在**买服务器的那家**提交，别换来换去 |
| **地域** | 学校的城市，如**华北 2（北京）** | 学生离得近，快一点 |
| **规格** | **轻量应用服务器，2 核 2G** 起步 | 这个应用极小，2G 绰绰有余，别买贵的 |
| **操作系统** | **Ubuntu 24.04 LTS** | ★ `gunicorn 26.2.0` 要求 **Python ≥ 3.10**，24.04 自带 3.12；**别选 20.04**（自带 3.8，装不上） |

> 买的时候**至少买 3 个月** —— 备案要求服务器剩余时长够（通常 ≥3 个月），
> 买 1 个月的话备案入口可能直接不给你开。

## 2. 买域名

在哪买都行（阿里云/腾讯云的域名服务，或任何域名商）。**挑一个**：

- **后缀**：`.com` / `.cn` / `.top` 都行。个人备案 `.cn` 一般更顺。
- **名字**：**短、好念、好拼** —— 学生要手输。
  例：`fenzhenzhan.com`、`sdt-lab.cn`

### ★ 关键一条：实名认证的人 = 后面备案的人

域名买完要做**实名认证**（1~3 天）。**认证用的身份证，必须和备案主体是同一个人**，
否则备案会被打回。**别用同学的名字买域名、你的名字去备案。**

---

## 3. 买服务器

1. 进云厂商的 **「轻量应用服务器」**（不是 ECS/CVM —— 轻量更便宜、够用、控制台更简单）
2. 地域：第 1 步定的
3. 镜像：**Ubuntu 24.04 LTS**（有些界面叫「系统镜像」→「Ubuntu」→ 选 24.04）
4. 规格：2 核 2G
5. 购买时长：**≥3 个月**
6. 买完记下**公网 IP**（形如 `123.45.67.89`）

### ★ 放行端口（这一步漏了，后面全连不上）

在服务器的 **「防火墙」/「安全组」** 页面，确认放行这三条：

| 端口 | 协议 | 干嘛的 |
|---|---|---|
| `22` | TCP | SSH 登录 |
| `80` | TCP | 网站（HTTP，也是申请证书要用的） |
| `443` | TCP | 网站（HTTPS） |

**轻量服务器一般默认就开 22/80/443。** 如果打不开网站，第一件事回来查这里。

## 4. ★ 备案 —— 最耗时的一步，尽早开始

### 为什么必须做

**服务器在大陆 + 绑定域名 = 必须 ICP 备案。** 不备案的话，
用域名访问 80/443 会被运营商拦截，页面打不开。

（**不绑域名、只用 IP 访问**不需要备案 —— 但你就没有 HTTPS、
学生要输 `http://123.45.67.89` 这种网址，而且 IP 会变。你既然要长期站点，就走备案。）

### 入口在哪

在**买服务器那家**云厂商的控制台搜 **「备案」**。它会认出你名下的服务器
（前提是买够时长），给你一个**备案服务号**，然后在线填资料提交。

### 需要准备

| 要什么 | 说明 |
|---|---|
| 身份证 | 正反面照片 |
| 手机号、邮箱 | 会用来收验证码和通知 |
| **真实住址** | 个人备案要填，会核对 |
| 域名 | 必须**已通过实名认证**，且**认证人 = 你** |
| 服务器的**备案服务号** | 云厂商控制台给你 |

### 流程大概是这样

```
在云厂商备案页面填资料 → 上传证件、人脸核验
        ↓
云厂商初审（1~2 个工作日，会打电话或发短信让你改）
        ↓
提交给省通信管理局审核（1~20 个工作日）
        ↓
通过 → 你拿到一个备案号，形如「京ICP备2026xxxxxx号-1」
```

### ★★ 最容易卡死的地方：个人备案的网站名称禁忌词

**个人备案的「网站名称」不允许出现这些：**

```
学校 / 大学 / 学院 / 教育 / 医院 / 政府 / 新闻 / 以及任何听起来像单位的词
（也不允许纯数字、纯英文）
```

**你这个项目是校内的教学实验，名字特别容易踩这个雷。** 所以：

- ❌ 别叫「北师大工程心理实验平台」「XX大学分诊实验站」
- ❌ 「急诊分诊台」我也建议避开 —— **「急诊」「医院」是医疗类字眼，容易被要求补材料**
- ✅ 起个中性的游戏名：**「分诊小站」**、**「分诊练习台」**、**「信号检测练习站」**

> **网站名称和页面上显示的名字可以不一样**，所以叫「分诊小站」完全不影响
> 学生在页面里看到「急诊分诊台」。
>
> **被驳回不等于完蛋** —— 按要求改个名字重新提交就行，但**每轮要重新排队等**。
> 所以名字一次起对，别浪费一轮。

### 备案审核期间，你能干什么

**能做的**：第 5~8 步全部可以先做（连服务器、装服务、配 nginx 都行）。
**不能做的**：**别把域名解析到这台服务器** —— 未备案域名在大陆服务器上是访问不了的，
解析过去也打不开，还可能影响审核。

**先只在服务器上用 `curl http://127.0.0.1:5055/` 本地验，够用了。**

### 备案通过之后，★ 还有两件法定义务

这两件**很多人会漏**，但都是要求：

**① 备案号必须挂在网站底部，并链接到工信部**

页脚得有一行，形如：

```html
<a href="https://beian.miit.gov.cn/" target="_blank">京ICP备2026xxxxxx号-1</a>
```

**这个我可以帮你加到页脚** —— 拿到备案号之后告诉我。

**② 30 天内还要做一次「公安联网备案」**

到 **全国互联网安全管理服务平台**（`beian.mps.gov.cn`）再提交一次。
这是**另一套系统**，和工信部备案不是一回事，别以为拿到备案号就完事了。

## 5. 搭服务（备案审核期间就能做）

以下命令在你自己电脑的**终端**里敲，一行一行来。

### 5.1 登录服务器

```bash
ssh root@你的公网IP
```

第一次会问 `Are you sure you want to continue connecting?` → 输 `yes` 回车，
然后输服务器密码（买的时候设的）。

**看到提示符变成 `root@...:~#` 就登进去了。** 之后这里敲的每条命令，都是在**服务器**上执行。

### 5.2 装东西

```bash
apt update
apt install -y python3-venv python3-pip nginx git sqlite3
```

- `python3-venv` —— 给项目单独建一套 Python 环境，不污染系统
- `nginx` —— 挡在前面的代理（第 7 步用）
- `sqlite3` —— 备份数据库要用
- `git` —— 拉代码

### 5.3 建一个专用用户 + 目录

**别用 root 跑网站服务。** 建一个只能管这摊事的普通用户：

```bash
useradd --system --create-home --shell /usr/sbin/nologin sdt
mkdir -p /opt/sdt /var/lib/sdt /var/backups/sdt
chown -R sdt:sdt /var/lib/sdt /var/backups/sdt
```

| 目录 | 放什么 |
|---|---|
| `/opt/sdt` | 代码 |
| `/var/lib/sdt` | 数据库（★ 故意放在代码目录**外面**） |
| `/var/backups/sdt` | 备份（第 10 步的定时任务往这写） |

> **为什么数据库不放代码目录里？** 这样你更新代码（`git pull`）时
> 不可能误伤数据，备份也只需要盯一个目录。

### 5.4 拉代码

```bash
cd /opt/sdt
git clone https://github.com/BNU-EngPsy-Fall26/LiuLing202628061012.git .
```

**★ 注意最后那个孤零零的点 `.`** —— 它的意思是「把仓库内容直接放当前目录」，
不加的话会多套一层文件夹。

> 如果仓库是私有的，会要你输账号和 **Personal Access Token**（不是账号密码）。
> 懒得弄的话，公有仓库直接过。

### 5.5 建 Python 环境、装依赖

```bash
cd /opt/sdt
python3 -m venv venv
./venv/bin/pip install --upgrade pip
./venv/bin/pip install -r server/requirements.txt
```

**★ 是 `server/requirements.txt`，不是根目录的** —— 依赖清单在 `server/` 里面。

### 5.6 设口令和数据位置

```bash
mkdir -p /etc/sdt
printf 'SDT_ADMIN_PASSWORD=%s\nSDT_DB_PATH=/var/lib/sdt/sdt.db\n' "$(head -c 18 /dev/urandom | od -An -tx1 | tr -d ' \n')" > /etc/sdt/sdt.env
chmod 600 /etc/sdt/sdt.env
```

**这条命令会随机生成一个 18 字节（36 位十六进制）的强口令**，
存到 `/etc/sdt/sdt.env` 里，权限设成只有 root 能读。

**现在把它抄下来 —— 你以后进教师后台就用这个：**

```bash
cat /etc/sdt/sdt.env
```

屏幕上 `SDT_ADMIN_PASSWORD=` **后面那一长串**就是口令。
**复制粘贴用**，别手打（36 位手打必错）。存到你的密码管理器里。

想自己指定口令也行（**别用 `admin123`**，那是源码里的公开默认值）：

```bash
printf 'SDT_ADMIN_PASSWORD=%s\nSDT_DB_PATH=/var/lib/sdt/sdt.db\n' '你想起的口令' > /etc/sdt/sdt.env
chmod 600 /etc/sdt/sdt.env
```

### 5.7 让代码和数据归 sdt 用户所有

```bash
chown -R sdt:sdt /opt/sdt
```

## 6. 把它做成一个常驻服务（systemd）

这样**开机自动启动、崩了自动重启**，不用你盯着。

### 6.1 建服务文件

```bash
cat > /etc/systemd/system/sdt.service <<'EOF'
[Unit]
Description=SDT Lab (Flask + gunicorn)
After=network.target

[Service]
User=sdt
Group=sdt
EnvironmentFile=/etc/sdt/sdt.env
WorkingDirectory=/opt/sdt
ExecStart=/opt/sdt/venv/bin/gunicorn --chdir /opt/sdt/server app:app \
          --bind 127.0.0.1:5055 --workers 1 --threads 4 \
          --access-logfile - --error-logfile -
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF
```

### 6.2 ★★ `--workers 1` 绝对不许改 —— 这条最要紧

**以后你要是上网搜 gunicorn 优化，一定会看到「加 `--workers 4` 提升性能」。
千万别加。**

**原因**：这个应用的后台登录 token 存在**进程内存**里
（`server/app.py` 里的 `VALID_TOKENS`，一个模块级集合）。

```
开 4 个 worker 会变成这样：

老师点「登录」  → 请求落到 worker 1 → token 存在 worker 1 的内存里
老师点「刷新」  → 请求落到 worker 3 → worker 3 不认识这个 token
                → 「未登录或登录已过期」→ 老师被踢回登录页
```

**症状是「教师后台随机掉线」**，而且**四分之三的请求都会掉**，极难查
—— 你会以为是网络问题、是浏览器问题，就是想不到是 worker 数。

**要并发怎么办**：用 `--threads 4`（上面已经写了）。
**线程共享同一份内存**，所以 token 是通的。

> 我已经在 `server/app.py` 里 `VALID_TOKENS` 旁边加了这条警告注释。
> 别删它。

### 6.3 启动

```bash
systemctl daemon-reload
systemctl enable --now sdt
systemctl status sdt
```

**看到绿色的 `active (running)` 就成了**（按 `q` 退出这个界面）。

### 6.4 立刻验一下

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5055/
```

**期望：`200`。** 出现 `200` 说明应用在服务器上跑起来了 —— **备案审核期间，
你验到这一步就够了**。

**不是 200 就看日志**：

```bash
journalctl -u sdt -n 50 --no-pager
```

## 7. 配 nginx（反向代理）

### ★★ 先看这条警告 —— 写错会泄漏全班成绩

**网上的 nginx 教程几乎都会让你写 `root /var/www/你的项目`。
这个项目绝对不能那么写。**

```
如果你写了 root 指向仓库目录
        ↓
nginx 会把仓库当静态网站目录直接伺服
        ↓
你的网址/server/sdt.db  →  浏览器直接下载到全班成绩 ★★★
你的网址/server/app.py  →  下载到后端源码
```

**正确做法：nginx 什么都不伺服，所有请求原样转发给 gunicorn。**
让 `server/app.py` 里那套白名单当**唯一**关卡。

### 7.1 建站点配置

```bash
cat > /etc/nginx/sites-available/sdt <<'EOF'
server {
    listen 80;
    listen [::]:80;
    server_name 你的域名.com www.你的域名.com;

    # ★★ 这里故意不写任何 root / index —— nginx 不碰任何文件
    #    所有请求全部转发给 gunicorn，白名单由 Flask 负责
    location / {
        proxy_pass http://127.0.0.1:5055;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
```

**★ 改这一处**：把两处 `你的域名.com` 换成你实际买的域名
（`www` 那个如果你没解析可以删掉整行）。**改完再往下走。**

### 7.2 启用并检查

```bash
ln -sf /etc/nginx/sites-available/sdt /etc/nginx/sites-enabled/sdt
rm -f /etc/nginx/sites-enabled/default
nginx -t
```

**期望看到 `syntax is ok` 和 `test is successful`。** 不是的话**别继续**，
把输出贴给我。

### 7.3 生效

```bash
systemctl reload nginx
```

**现在**（备案还没通过、域名还没解析）用 IP 就能验：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/admin.html
```

**期望 `200`。**

## 8. HTTPS（★ 等备案通过、域名能访问之后再做）

**前提三条，缺一不可**：

1. 备案**已经通过**
2. 域名**已经解析**到这台服务器的公网 IP
   （在云厂商的「域名解析」里加一条 `A` 记录，主机记录填 `@`，值填公网 IP；
   再加一条主机记录 `www` 指向同一个 IP）
3. `http://你的域名` 在浏览器里**能正常打开**

三条都满足后再来：

```bash
apt install -y certbot python3-certbot-nginx
```

```bash
certbot --nginx -d 你的域名.com -d www.你的域名.com
```

它会问你邮箱（填真实的，证书快过期时会提醒）、问是否同意条款（输 `A`）、
问要不要把 HTTP 自动跳转到 HTTPS（**选 2，重定向**）。

**它会自动改好第 7 步那个 nginx 配置、自动配好证书。**

### 验一下自动续期

Let's Encrypt 的证书**只有 90 天**，但 certbot 装好了会自动续。确认一下：

```bash
systemctl list-timers | grep certbot
```

能列出东西就说明自动续期在跑。手动演练一次：

```bash
certbot renew --dry-run
```

**看到 `Congratulations, all simulated renewals succeeded` 就对了。**

## 9. ★ 上线验收（十条，一条不对就停下）

现在终于可以按 [部署步骤.md](部署步骤.md) 第 7 步那套验了。
**换了 nginx 之后，安全那三条必须重新验一遍** —— nginx 配置写错，
白名单可能整片失效。

```bash
D=你的域名.com
for u in / /admin.html /server/app.py /server/sdt.db /CONTRACT.md /.git/config /server/db.py; do
  printf '%-20s %s\n' "$u" "$(curl -s -o /dev/null -w '%{http_code}' https://$D$u)"
done
```

**期望（左边三条 200，右边四条 404）：**

| 路径 | 期望 | 意味着 |
|---|---|---|
| `/` | **200** | 学生端 |
| `/admin.html` | **200** | 教师端 |
| `/server/app.py` | **404** | 后端源码没泄漏 |
| `/server/sdt.db` | **404** | ★★★ **全班成绩没泄漏** |
| `/CONTRACT.md` | **404** | 内部文档没泄漏 |
| `/.git/config` | **404** | 连 `.git` 目录都没暴露 |
| `/server/db.py` | **404** | |

**★ 只要 `/server/sdt.db` 返回 200 或 403（而不是 404），立刻停下**，
说明 nginx 在直接伺服文件 —— 回去看第 7 步那条警告。

### 然后在浏览器里真机走一遍

1. 电脑上打开 `https://你的域名/` → 学生端出来了，地址栏**有小锁**
2. 打开 `https://你的域名/admin.html` → 填第 5.6 步那个口令 → **能进去**
3. 玩一局**快速版**（48 试次，约 9 分钟，前面还有一小段练习轮）
4. 回后台**刷新** → 你那一行在表格里
5. 点 **「导出全班 CSV」** → 下载下来，**用 Excel 打开中文不乱码**
6. **手机流量**（关 WiFi，别用教室网络）打开 → 登录 → 三轮 → 结果 → 实验室，
   看布局有没有塌

## 10. 备份（★ 长期站点必须做，别跳过）

服务器是你自己的，所以**再也不会有「重新部署就清空」的问题**。
但硬件会坏、手会抖、数据库文件会坏。**备份是唯一能救回来的东西。**

### 10.1 建一个备份脚本

```bash
cat > /usr/local/bin/sdt-backup <<'EOF'
#!/bin/bash
set -euo pipefail
D=/var/backups/sdt
mkdir -p "$D"
# .backup 是 sqlite 官方的安全备份方式，服务在跑的时候也能用
sqlite3 /var/lib/sdt/sdt.db ".backup '$D/sdt-$(date +%F).db'"
gzip -f "$D/sdt-$(date +%F).db"
# 只留最近 30 天
find "$D" -name 'sdt-*.db.gz' -mtime +30 -delete
EOF
chmod +x /usr/local/bin/sdt-backup
```

### 10.2 每天凌晨跑一次

```bash
(crontab -l 2>/dev/null; echo "17 3 * * * /usr/local/bin/sdt-backup") | crontab -
```

**注意是 `17 3`（凌晨 3:17），不是整点** —— 整点大家都挤在一起跑。

### 10.3 立刻试一次，别等明天

```bash
/usr/local/bin/sdt-backup
ls -lh /var/backups/sdt/
```

**看到 `sdt-2026-10-10.db.gz` 这种文件就成了。**

### 10.4 ★ 但备份在本机上不算备份

**服务器整个坏掉、或者你误删了，本机备份跟着一起没。**
所以还要**往外拿一份** —— 三条路，至少做一条：

| 做法 | 说明 |
|---|---|
| **教师后台点「导出全班 CSV」** | 每收一批就点一次，下载到自己电脑。**最简单，也最该做** |
| 定时同步到对象存储 | 云厂商的 OSS/COS，几块钱一年。定期把 `/var/backups/sdt/` 传上去 |
| 你自己定期 `scp` 下来 | 在**你自己电脑**上跑：`scp root@公网IP:/var/backups/sdt/*.gz ~/Downloads/` |

**实验收尾时，无论如何都要做一次「导出全班 CSV」。** 那是人能直接看的、
不依赖任何工具的最终凭证。

## 11. 日常运维速查

| 我想…… | 敲什么 |
|---|---|
| **改代码后更新** | `cd /opt/sdt && git pull && systemctl restart sdt` |
| 重启服务 | `systemctl restart sdt` |
| 看服务活着没 | `systemctl status sdt` |
| 看日志（实时） | `journalctl -u sdt -f` |
| 看最近 50 行日志 | `journalctl -u sdt -n 50 --no-pager` |
| 看 nginx 报错 | `journalctl -u nginx -n 50 --no-pager` |
| 改教师口令 | 改 `/etc/sdt/sdt.env` 后 `systemctl restart sdt` |
| 手动备份一次 | `/usr/local/bin/sdt-backup` |
| 从备份恢复 | 见下 |
| 续证书 | 自动的。手动演练：`certbot renew --dry-run` |

### 从备份恢复

```bash
systemctl stop sdt
gunzip -c /var/backups/sdt/sdt-2026-10-10.db.gz > /var/lib/sdt/sdt.db
chown sdt:sdt /var/lib/sdt/sdt.db
systemctl start sdt
```

> ⚠️ 改代码（`git pull`）**之后要 `systemctl restart sdt`** ——
> 光拉代码不会自动生效。而且**先确认拉下来的东西没问题**：
> 更新代码不会清数据库（数据库在 `/var/lib/sdt`，不在仓库里），
> 但改坏了应用会让学生玩不了。

### 安全上再上两道锁（建议做）

```bash
# ① 系统自动打安全补丁
apt install -y unattended-upgrades
dpkg-reconfigure -plow unattended-upgrades

# ② 只允许用密钥登录（先确认你已经配好了 SSH 密钥，别把自己关在门外）
```

**② 有风险，不懂就别做** —— 配错了你会永远登不上服务器。
真要做得先配好密钥、在另一个终端验证能登进去，再关密码登录。

## 附二：常见故障对照表

| 症状 | 多半是 | 怎么办 |
|---|---|---|
| 浏览器「无法访问此网站」 | 安全组没放行 80/443 | 回第 3 步的防火墙页面 |
| 502 Bad Gateway | gunicorn 没起来 | `systemctl status sdt` + `journalctl -u sdt -n 50` |
| 域名能 ping 通但网页打不开 | ★ 备案没通过 | 查备案进度；备案前只能用 IP |
| `/server/sdt.db` 能下载 | ★★★ nginx 写成了 `root` | **立刻**按第 7 步改掉并 `systemctl reload nginx` |
| 教师后台**随机**掉线、要反复登录 | ★ 给 gunicorn 加了 `--workers` | 改回 `--workers 1`，并发用 `--threads` |
| 提示「密码错误」但你没打错 | 口令里有空格 / 复制漏了字符 | `cat /etc/sdt/sdt.env` 重新复制一遍 |
| 证书快到期 | 自动续期没跑 | `systemctl list-timers \| grep certbot`，手动 `certbot renew` |
| 磁盘满了 | 日志或备份堆积 | `df -h`；日志 `journalctl --vacuum-time=30d`；备份按第 10 步自动只留 30 天 |
| 服务活着但网页是旧代码 | 拉了代码没重启 | `systemctl restart sdt` |
