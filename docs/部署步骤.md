# 把「急诊分诊台」放到网上 —— 用 Railway（带你自己的域名）

> 这份文档假设你**完全不懂命令行**。每一步都写清楚「点哪里、填什么、在哪一页」。
> 凡是需要敲命令的地方，都会标出来「如果不敢敲，可以怎么做」。

> ### 这是本项目的主路线
>
> **Railway 是一个「平台即服务」（PaaS）**：你不用买服务器、不用管系统，
> 把 GitHub 仓库连上去它就跑起来。**服务器在海外，所以不用 ICP 备案**
> —— 域名买来几分钟就能用。
>
> **要更快的访问速度**（学生打开快几十倍）就得把服务器放回国内，
> 那条路要**买服务器 + ICP 备案（1~20 个工作日）+ 自己管 nginx/证书/备份**，
> 见 [`部署手册-自有服务器.md`](部署手册-自有服务器.md)。**两条路用同一份代码。**

---

## 先说最重要的：**这件事失败了，作业照样能交**

部署**不是**必须成功的事。这个应用里已经准备好了一条兜底的路：

```
学生玩完 → 结果页点「导出成绩单」→ 浏览器下载一个 CSV 文件
        ↓
交给班长汇总（微信 / 邮箱都行）→ 一个人发给老师
        ↓
老师用 Excel 打开就能看
```

**这条路不依赖服务器、不依赖网络、任何时候都能走。**

所以：**照下面的步骤做，做不通就回来看本节开头这条兜底方案，不要卡在这里。**

## 第 1 步：代码已经改好了，你不用动

为了让 Railway 认得这个项目，仓库根目录已经加了三个文件。
**你只需要知道它们是干嘛的，一个都不用改：**

| 文件 | 干嘛的 |
|---|---|
| `requirements.txt`（根目录） | ★ **最关键**。内容是 `-r server/requirements.txt`。Railway 判断「这是不是 Python 项目」看的是**根目录**有没有这个文件；我们真正的依赖清单在 `server/` 子目录里，根目录不放一个的话，**平台认不出来，构建直接失败** |
| `.python-version` | 钉死 Python 版本（`3.13.2`），避免以后平台换默认版本导致装不上依赖 |
| `railway.json` | 告诉 Railway 用什么命令启动（里面那条命令**不要改**，见第 6 步） |

**要改代码的话**：在本机改完 `git push` 上去，Railway 会**自动重新部署**。
（这次有持久磁盘，所以重新部署**不会**清库 —— 但别在实验进行中乱推。）

## 第 4 步：设两个环境变量

在 Railway 的项目画布上**点一下你那个服务**，左侧选 **`Variables`** 标签。
点 **`New Variable`** 一条一条加：

### 变量一：教师口令

| 名字（`Variable Name`） | 值（`Value`） |
|---|---|
| `SDT_ADMIN_PASSWORD` | 你要给老师用的口令 |

**怎么起这个口令：**

- ❌ **不要用** `admin123` —— 那是代码里的默认值，**这行代码是公开的**，
  任何看过源码的人都知道。**你不设这个变量，后台就等于没锁。**
- ❌ 不要用老师的学号、生日、手机号
- ✅ 用**一句话**当口令，好记又难猜。例如：`北楼302分诊台2026`

**加完之后在心里念一遍，确认没多打空格。**

> ### ⚠️ 口令定好就别改了
>
> 改环境变量会触发一次**重新部署**。如果第 5 步的磁盘没挂好，
> **重新部署就是清空全班成绩**。**现在一次定好。**

### 变量二：数据库放在哪

| 名字 | 值 |
|---|---|
| `SDT_DB_PATH` | `/data/sdt.db` |

意思是「把成绩存在 `/data` 文件夹下的 `sdt.db`」。`/data` 就是下一步要挂的磁盘。

> ⚠️ **这一条必须和第 5 步配对做。**
> 只设变量不挂磁盘 → 文件写在一次性的硬盘上；
> 只挂磁盘不设变量 → 白买了块盘子。
> **两件事一起做才有用。**

## 第 5 步：★ 挂持久磁盘（Volume）到 `/data`

**这一步是「成绩会不会丢」的唯一保障，别跳过。**

1. 在项目画布上按 **`⌘K`**（Windows 是 `Ctrl+K`）打开命令面板，
   或者在空白处**右键**，找 **`Volume`** / **`Create Volume`**
2. 它问你挂到哪个服务 —— 选你刚建的那个服务
3. **★ 设挂载路径（Mount Path）：填 `/data`** —— 必须和第 4 步的
   `SDT_DB_PATH=/data/sdt.db` 对得上
   （在服务的 `Settings` → `Volumes` 里能改）

> ### 容量和数量（2026-10-10 抓的定价页）
>
> - **Hobby**：5 GB，一个项目最多 10 个卷
> - **Free**：0.5 GB，一个项目**只能 1 个**
>
> 一场实验的成绩也就几百 KB —— **0.5 GB 都绰绰有余**，别纠结容量。
>
> ### ⚠️ 磁盘是「容器启动时」才挂上去的
>
> 构建的时候还没有。这一点对本项目**没有影响**（数据库是程序运行时才建的），
> 但你要是以后自己加了「构建时写文件」的步骤，得知道它不会落到磁盘上。

## 第 6 步：确认启动命令（一般不用动）

`railway.json` 已经写好了，Railway 会自动读它。里面那条命令是：

```
gunicorn --chdir server app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4
```

### ★★ `--workers 1` 绝对不许改 —— 这条最要紧

**以后你要是上网搜 gunicorn 优化，一定会看到「加 `--workers 4` 提升性能」。千万别加。**

**原因**：后台登录 token 存在**进程内存**里（`server/app.py` 的 `VALID_TOKENS`）：

```
开 4 个 worker 会变成：

老师点「登录」 → 请求落到 worker 1 → token 存在 worker 1 的内存里
老师点「刷新」 → 请求落到 worker 3 → worker 3 不认识这个 token
              → 「未登录或登录已过期」→ 被踢回登录页
```

**症状是「教师后台随机掉线」**，四分之三的请求都会掉，极难查
—— 你会怀疑网络、怀疑浏览器，就是想不到是 worker 数。

**要并发用 `--threads`**（上面已经写好了）。线程共享同一份内存，token 是通的。

> `docs/部署手册-自有服务器.md` 第 6.2 节有同样的说明，
> `server/app.py` 里 `VALID_TOKENS` 旁边也有注释。

### 现在让它重新部署一次

环境变量和磁盘都配好了，在服务页面点 **`Deploy`** / `Redeploy`，
或者右上角 `⋮` → `Redeploy`。

**接着就是等**，第一次构建通常 2~5 分钟。看 **`Deployments`** 标签里滚动的日志。
构建成功后 Railway 会给你一个**临时网址**（形如 `xxx.up.railway.app`）——
**先用它验，再去配自己的域名。**

## 第 7 步：★ 把你买的域名指过来

1. 进服务 → `Settings` → **`Networking`** / `Public Networking`
2. 找到 **`Custom Domain`**，点 **`Add Custom Domain`**，填你买的域名
   （例如 `fenzhenzhan.com`；想连 `www` 就再加一条 `www.fenzhenzhan.com`）
3. **★ Railway 会给你两条 DNS 记录，两条都要加：**

   | 类型 | 名称 | 值 |
   |---|---|---|
   | `CNAME` | 你的域名 | Railway 给你的一串 |
   | `TXT` | Railway 给你的一串 | Railway 给你的一串 |

   **少加 TXT 那条，验证会一直不过**（这是最常见的坑）。

4. 去**你买域名的地方**（阿里云/腾讯云/Namecheap…）找 **「解析」/ `DNS`**，
   把上面两条记录照着加进去，保存

5. **回 Railway 等它验证** —— 通常几分钟到半小时（DNS 生效要时间）。
   验证通过后 Railway 会**自动配好 HTTPS 证书**，你不用做任何事。

> **国内域名商的解析页面**可能叫「云解析 DNS」或「域名解析」，
> 加记录的地方写着「添加记录」。**主机记录**那一栏：
> 根域名填 `@`，`www` 就填 `www`。

## 第 9 步：出错了看哪里

在 Railway 的服务页面，有两个不一样的地方，**别搞混**：

| 标签 | 里面是什么 |
|---|---|
| **`Deployments`** | **构建**日志 —— 「装依赖、起服务」那一段。**启动不起来看这里** |
| **`Logs`**（或 `Observability`） | **运行时**日志 —— 服务跑起来之后应用说的话。**学生报错看这里** |

| 日志里看到 | 说明 | 怎么办 |
|---|---|---|
| 构建阶段说**找不到 Python** / 没装任何依赖 | 根目录少了 `requirements.txt` | 确认仓库根目录有 `requirements.txt`（第 1 步那个文件），没有的话 `git push` 补上 |
| `No module named 'app'` | 启动命令里的目录切错了 | 检查 `railway.json` 里的命令有没有 `--chdir server` |
| `No module named 'flask'` | 依赖没装上 | 看构建日志；确认根目录 `requirements.txt` 里的 `-r server/requirements.txt` 那一行还在 |
| `Address already in use` | 端口写死了 | 启动命令里必须是 `$PORT`，**不能写死的数字** |
| `unable to open database file` | 磁盘没挂上 / 路径不对 | 第 5 步的挂载路径是不是 `/data`？`SDT_DB_PATH` 是不是 `/data/sdt.db`？**两个必须一致** |
| 部署成功但网页 502 | 服务起来了又崩了 | 看 `Logs` 里的报错，截图给我 |

**改了环境变量不生效？** 要**重新部署一次**（`Redeploy`）才会生效。
（有持久磁盘的话不会丢数据。）

## 第 10 步：收作业 —— 备份

**有持久磁盘了，理论上不会丢。但备份还是要做 —— 硬盘也会坏，手也会抖。**

先说清这个应用里的两个「导出」按钮：

| 在哪 | 叫什么 | 导出什么 |
|---|---|---|
| 教师后台工具栏 | **导出全班 CSV** | 全班一人一行，一张表 |
| 学生结果页 | 导出成绩单 | 这位学生自己那一场 |

### 路线 A（最快）：教师后台点「导出全班 CSV」

1. 打开 `你的域名/admin.html`，输口令进后台
2. 点**导出全班 CSV**，浏览器下载 `sdt-全班-2026-10-10.csv`
3. 用 Excel 打开 —— 学号、姓名、模式、三轮的 d′/c/准确率、总 d′/总 c/总准确率、提交时间
4. **存三份**：电脑、U 盘、网盘或邮箱发自己一份

两条要注意的：

- 导出的是**当前表格里显示的那些人**。筛了「快速版」就只导快速版；
  要导全班先点「全部」。搜索框里还留着字也会算数。
- 一个人都没交卷时按钮是灰的 —— 故意的，不给你一个只有表头的空文件。

### 路线 B（★ 最后一道保险）：让学生各自导出

```
学生玩完 → 结果页点「导出成绩单」→ 下载到一个 CSV
        ↓
班长收齐 → 打包发给老师 → 老师用 Excel 打开
```

**完全不依赖教师后台和服务器。** 就算 Railway 欠费被停、账号出问题，
学生手上那份文件还在。**所以部署整个失败了作业也照样能交。**

```
出问题看哪里：  Deployments（构建）/ Logs（运行时）
```

## 附二：常见故障速查

| 症状 | 多半是 | 怎么办 |
|---|---|---|
| 构建失败，说找不到语言/依赖 | 根目录缺 `requirements.txt` | 第 1 步那个文件要推上去 |
| 部署成功但打开是错误页 | 启动命令或环境变量不对 | `Deployments` 的日志，对着第 9 步的表 |
| 能玩但后台看不到成绩 | ★ 磁盘没挂 / 路径不一致 | 第 5 步挂载点必须 `/data`，和第 4 步的 `SDT_DB_PATH` 一致 |
| 教师后台**随机**掉线 | ★ 有人加了 `--workers` | 改回 `--workers 1`（第 6 步） |
| 域名一直验证不通过 | ★ 只加了 CNAME，漏了 TXT | 第 7 步两条都要加 |
| 域名能打开但没小锁 | 证书还在签 | 等十分钟；还不行就删掉域名重新加一次 |
| 服务隔一阵就打不开（要等十几秒） | 免费档休眠 | 换 Hobby，或先忍着（开着的服务不会休眠） |
| Railway 欠费服务被停 | 额度用完 | 充钱，或按第 10 步走路线 B |
