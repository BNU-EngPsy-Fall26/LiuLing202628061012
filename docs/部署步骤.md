# 把「急诊分诊台」放到网上 —— 给非程序员的步骤说明

> 这份文档假设你**完全不懂命令行**。每一步都写清楚「点哪里、填什么、在哪一页」。
> 凡是需要敲命令的地方，都会标出来「如果不敢敲，可以怎么做」。

---

## 先说最重要的：**这件事失败了，作业照样能交**

部署**不是**必须成功的事。这个应用里已经准备好了一条兜底的路：

```
学生玩完 → 结果页点「导出成绩单」→ 浏览器下载一个 CSV 文件
        ↓
交给班长汇总（微信 / 邮箱都行）→ 一个人发给老师
        ↓
老师用 Excel 打开就能看
```

**这条路不依赖服务器、不依赖网络、任何时候都能走。**

所以：**照下面的步骤做，做不通就回来看本节开头这条兜底方案，不要卡在这里。**
（第 9 步「收作业」会告诉你为什么这件事要提前想好。）

另外：**你不需要懂代码。** 整个应用已经写好了，下面做的只是「把它搬到一台
一直开着的电脑上，并且告诉这台电脑两件事：教师口令是什么、成绩存到哪」。

## 第 1 步：把代码放到 GitHub 上

平台是从 GitHub 上「拉」代码来运行的，所以代码得先在 GitHub 上。

### 1.1 先确认代码在不在 GitHub 上

打开浏览器，在地址栏输入 `github.com` 回车，登录你自己的账号，点右上角头像边上的
**「Your repositories」**，在列表里找有没有 `sdt-lab` 这个仓库。

- **有** → 跳到第 2 步。
- **没有** → 继续往下。

### 1.2 如果还没有：建仓库 + 传文件

不想碰命令行的话，用**网页上传**就够了：

1. 在 `github.com` 页面，点右上角的 **`+`** → **`New repository`**
2. **`Repository name`** 填：`sdt-lab`
3. 下面选 **`Private`**（私有）—— 里面是内部文档，不打算公开
4. 其余都别动，点最下面的绿色按钮 **`Create repository`**
5. 新页面上会有一行蓝字 **`uploading an existing file`**，点它
6. 把项目文件夹里的东西**全选、拖进网页中间的虚线框**：
   - `Procfile`、`README.md`、`CONTRACT.md`、`index.html`、`admin.html`
   - 四个文件夹：`server`、`js`、`styles`、`docs`
   - **`tasks` 文件夹可以不传**（那是施工记录，不影响运行）
   - **`server/sdt.db` 千万不要传** —— 那是本地的成绩库，线上会自己建一个新的
7. 拖完之后往下拉，点绿色按钮 **`Commit changes`**

> ⚠️ **两个最容易漏的**：
> - **`Procfile` 必须传**（它在项目最外层，不是 `server` 文件夹里面）。
>   没有它，平台不知道该用什么命令把应用启动起来。
> - 传完之后，回到仓库首页，应该能**一眼看到 `Procfile`** 这个名字。
>   看不到就是没传上去，回去补。

### 1.3 记下仓库地址

仓库首页地址栏里那串东西就是要的地址，长这样：

```
https://github.com/你的用户名/sdt-lab
```

**复制下来，第 3 步要用。**

## 第 2 步：选一个平台并注册

### ★ 选平台时唯一必须满足的条件

这个应用的成绩存在一个叫 SQLite 的**文件**里。问题在于：

> **服务器的硬盘是「一次性」的 —— 重新部署一次，容器重建，文件全没。**
> 对作业来说这是致命的：学生在几天里陆续交，你中途重新部署一次，全班成绩消失。

解决办法是给服务器**挂一块「持久磁盘」**（各平台的叫法不一样：
**Persistent Disk / Volume / 持久化存储 / 数据卷**），
然后把数据库放进这块盘里。**所以选平台时，第一件事是确认它支不支持持久磁盘。**

**免费档通常不支持** —— 这是常见的坑，别假设它有。

### 怎么确认（两分钟）

在平台的**定价页（Pricing）**上找这几个词：

| 找这个词 | 它在说什么 |
|---|---|
| `Persistent Disk` / `Volume` / `Disk` | 持久磁盘。有它才能保证成绩不丢 |
| `Free` / `Hobby` / `Starter` 后面的**月费** | 注意看「最低要花多少钱才能挂磁盘」 |

**下面这张表是写这份文档时的常见情况，供参考。**
平台政策改得很勤，**注册前自己看一眼定价页**，别只听这张表：

| 平台 | 免费档有没有？ | 能不能挂持久磁盘 |
|---|---|---|
| Render | 有免费 Web Service（闲置会休眠，冷启动要等几十秒） | 磁盘通常要求付费档 —— **要自己确认** |
| Railway | 一般只有试用额度，用完转付费 | 付费档支持磁盘 |
| Heroku | 已经没有免费档了 | 付费档支持，但最贵 |
| Fly.io | 按用量付费 | 支持 `Volume`，挂载点通常写 `/data` |

### 注册

流程各家都差不多：

1. 打开平台官网，点 **`Sign Up`** / **`Get Started`**
2. 有一项 **`Sign up with GitHub`** —— **选这个**，省得再记一个密码，
   而且它会把你的 GitHub 账号连起来（第 3 步就变成一键完成）
3. 它会让你**授权平台读你的仓库**，点同意
4. 邮箱里可能会收到一封验证信，点里面的链接

> **你不需要填信用卡就能注册。** 平台只在你要开付费功能（比如挂磁盘）时才问卡号。

## 第 3 步：把 GitHub 仓库连到平台

1. 登录平台后，找 **`New`** / **`New +`** / **`Create New`** 按钮，
   一般是页面右上角，或者控制台首页中间。
2. 在菜单里选 **`Web Service`**（不是 Static Site、不是 Database）。
3. 它会列出你 GitHub 里的仓库，选 **`sdt-lab`**。
   - 如果列表是空的或是「没找到仓库」，说明第 2 步授权时只给了部分仓库的权限。
     回 GitHub：右上角头像 → `Settings` → 左侧拉到最下面 `Applications` →
     找到这个平台 → 点 `Configure` → 选 `All repositories`（或把这个仓库勾上）。
4. **`Region`（地区）** 如果让你选，选离你最近的（比如 `Singapore` / `Tokyo`）——
   学生打开快一点。**注意：挂磁盘的平台一旦选好地区，通常不能改。**
5. 接下来它会让你填几项设置。**先别点「Deploy / 创建」**，看第 4、5、6 步。

## 第 4 步：设两个环境变量

**「环境变量」就是给服务器上这台应用留的小纸条**：不用改代码，就能告诉它
「教师口令是这个」「成绩存到那个地方去」。

在创建服务的那一页上找 **`Environment`** / **`Environment Variables`** /
**`Variables`** 这一类标题（有的平台藏在 `Advanced` / `高级设置` 折叠栏里）。
一条一条地加：

### 变量一：教师口令

| 名字 | 值 |
|---|---|
| `SDT_ADMIN_PASSWORD` | 你要给老师用的口令 |

**怎么起这个口令：**

- ❌ **不要用** `admin123` —— 那是代码里的默认值，**这行代码是公开的**，
  任何看过源码的人都知道。**你不设这个变量，后台就等于没锁。**
- ❌ 不要用老师的学号、生日、手机号
- ✅ 用**一句话**当口令，好记又难猜。例如：
  `北楼302分诊台2026` 、`sdt-实验-别告诉学生`

**加完之后自己在心里念一遍，确认没有多打空格。**

### 变量二：数据库放在哪

| 名字 | 值 |
|---|---|
| `SDT_DB_PATH` | `/data/sdt.db` |

这一串的意思就是「把成绩存在 `/data` 这个文件夹下的 `sdt.db` 文件里」。
`/data` 就是下一步要挂的那块持久磁盘。

> ⚠️ **这一条必须和第 5 步配对做。** 只设变量、不挂磁盘，等于把文件写在一次性硬盘上；
> 只挂磁盘、不设变量，等于把文件写在一次性硬盘上但白买了块盘子。
> **两件事一起做才有用。**

---

## 第 5 步：★ 挂一块持久磁盘，挂到 `/data`

**这一步是「成绩会不会丢」的唯一保障，别跳过。**

1. 在你正在配置的这个服务的设置里，找 **`Disks`** / **`Volumes`** /
   **`Persistent Disk`** / **`存储`** 这个标签页或者区块
2. 点 **`Add Disk`** / **`New Volume`**
3. 填三样：

   | 填什么 | 填成 |
   |---|---|
   | `Name`（名字） | `sdt-data`（随便起，只是个名字） |
   | `Mount Path`（挂载路径）**★ 最重要** | `/data` |
   | `Size`（大小） | 最小的那个就够（1 GB）。一场实验的成绩也就几百 KB |

4. 确认保存

> ### ⚠️ 如果平台的免费档不支持挂磁盘
>
> 那就**别花钱也别硬来**，改走这三条里的一条：
>
> 1. **冻结代码**：部署一次之后**中途绝对不重新部署**。学生交的几天里别动任何设置。
> 2. **只在实验当天开**：实验前部署，做完立刻做第 9 步（把成绩备份下来），然后关掉服务。
> 3. **不上线**：留在老师自己的电脑上跑（`cd server && python3 app.py`），
>    学生在同一个教室网络里访问；收完成绩照样走第 9 步备份。
>
> **第 1、2 条的要害都是同一句：只要收完数据就备份下来，
> 服务明天没了，成绩还在你手上。**

---

## 第 6 步：启动命令

**大多数平台什么都不用做 —— 它会自己读项目里那个 `Procfile`。**
那个文件里就一行：

```
web: gunicorn --chdir server app:app --bind 0.0.0.0:$PORT
```

如果你在设置页上看到这些框，按下面填：

| 框的名字 | 填什么 | 说明 |
|---|---|---|
| `Start Command` / `启动命令` | `web: gunicorn --chdir server app:app --bind 0.0.0.0:$PORT` | 有些平台**不用写开头的 `web:`**，那就填 `gunicorn --chdir server app:app --bind 0.0.0.0:$PORT` |
| `Build Command` / `构建命令` | `pip install -r server/requirements.txt` | ★ 注意是 `server/requirements.txt`，**不是根目录的** —— 依赖清单在 `server` 文件夹里 |
| `Root Directory` / `根目录` | **留空，不要填** | ★ 千万别填成 `server` —— 那会让网页文件全部找不到（解释见 `README.md`） |
| `Python Version` | 有就填 `3.12`；没有就算了 | 应用需要 Python 3.9 以上 |

填完点 **`Create Web Service`** / **`Deploy`**。

**接着就是等。** 第一次构建通常要 3~5 分钟。页面底部或者 `Logs` 标签页里会有
滚动的文字，那是在装依赖。看到类似 **`Listening at: http://0.0.0.0:xxxx`**
就说明起来了。

## 第 7 步：验证部署成功（按顺序，一条不对就停下）

平台会在页面上给你一个网址，形如 **`https://sdt-lab-xxxx.onrender.com`**。
**下面把它叫做「你的网址」。**

### 电脑上用浏览器打开

| # | 做什么 | 应该看到什么 | 不对怎么办 |
|---|---|---|---|
| 1 | 打开 `你的网址` | 学生端登录页出来了（能填学号和姓名） | 看第 8 步的 `Logs` |
| 2 | 打开 `你的网址/admin.html` | 教师端登录页（一个输口令的框） | 同上 |
| 3 | 在教师端填你第 4 步设的口令，点登录 | 进去了，能看到成绩表格 | 提示「口令错误」→ 回第 4 步检查变量名有没有拼错、值有没有多空格；改完要**重新部署**才生效 |
| 4 | 回学生端，随便填个学号姓名，玩一局**快速版**（约 9 分钟，之前还有一小段练习轮） | 能玩完，中途不卡 | 卡住的话按 F12 看 Console 红字（见下面） |
| 5 | 玩完回教师端，**刷新页面** | 你刚玩的那一行在表格里 | 不在 → 说明数据库没写进去，看第 8 步 |
| 6 | 在学生页面按 **F12**，点 **`Console`** | 没有红色字 | 有红字就把那行截图 |
| 7 | **打开 `你的网址/server/app.py`** | **404**（一个「找不到页面」的错误页） | ★ 如果**能下载到这个文件**，说明后端源码泄漏了，立刻停下来告诉写代码的人 |
| 8 | **打开 `你的网址/server/sdt.db`** | **404** | ★ 如果**下载到了文件**，说明**全班成绩可以被任何人下载**，最严重的一档，立刻停下 |
| 9 | **打开 `你的网址/CONTRACT.md`** | **404** | 同上，内部文档不该被访问到 |

**第 7、8、9 条最要紧。** 本地测试时是对的，线上也必须**重新验一遍** ——
部署配置里如果有哪一步改错了路径，白名单可能整片失效。

### 手机上也走一遍

用手机浏览器打开 `你的网址`：**登录 → 三轮 → 结果 → 实验室**，
看布局有没有塌、按钮点不点得到。学生八成是用手机玩的。

### 等一会儿再打开一次

免费档的服务**闲置一会儿会自动休眠**。先不管它，**过 20 分钟再打开网址**：
第一次可能要等十几秒才醒（页面转圈），醒过来就正常了 —— 这是免费的代价，不是坏了。

## 第 8 步：出错了看哪里

### 看日志（`Logs`）

平台的服务页面上有一个 **`Logs`** 标签页，里面是这个应用运行时说的话。
**先看最下面几行**，那里是最新的。

| 日志里看到 | 说明 | 怎么办 |
|---|---|---|
| `No module named 'app'` | 启动命令里的目录切错了 | 检查启动命令里有没有 `--chdir server`；检查平台的「根目录 / Root Directory」是不是被你填成了 `server`（应该留空） |
| `No module named 'flask'` | 依赖没装上 | 检查构建命令是不是 `pip install -r server/requirements.txt` |
| `Address already in use` | 端口被别人占了 | 启动命令里的 `$PORT` 是不是被写成了固定数字？平台给的就是 `$PORT`，**不能改** |
| `Permission denied` / `unable to open database file` | 数据库路径写不通 | 第 5 步的磁盘是不是真的挂到了 `/data`？`SDT_DB_PATH` 是不是写成 `/data/sdt.db`？ |
| 一大段滚动后最后停在 `Worker failed to boot` | 起不来 | 把这一屏截图，连同前面的报错一起发给写代码的人 |

### 网页本身出问题：看浏览器的 Console

1. 在出问题的网页上按 **F12**（Mac 是 `Option + Command + I`）
2. 上方点 **`Console`** 标签
3. 只看**红色**的字。把红字截图。

常见的红字之一是 `404 (Not Found)` 后面跟着 `/api/...` ——
说明页面在跟后端说话，后端没答应。这时候去看平台的 `Logs`。

### 改了设置但没生效？

平台上的**环境变量改了，要重新部署一次才会生效**（在服务页面点
`Redeploy` / `重新部署` / `Manual Deploy`）。

> ⚠️ 但如果你的免费档**没有持久磁盘**，**重新部署 = 清空数据库**。
> 动手之前先把成绩备份下来（第 9 步）。这一条再怎么强调都不为过。

## 第 9 步：收作业 —— 一定要提前做的事

**不管部署成功还是失败，实验收尾时都做这一步。**

先说清一个事实：**这个应用的「导出」按钮只在学生端有（结果页的「导出成绩单」），
教师后台没有「一键导出全班 CSV」这种按钮。** 所以全班备份有三条路，
从省事到保险排：

### 路线 A（最快）：从后台表格复制进 Excel

1. 打开 `你的网址/admin.html`，输口令进后台
2. 用鼠标按住，从表格**第一行的第一格**拖到**最后一行的最后一格**（把整张表选中）
3. `Ctrl + C`（Mac 是 `Cmd + C`）
4. 打开 Excel，点第一个格子，`Ctrl + V`
5. 另存成 `.xlsx`，**存三份**：电脑、U 盘、网盘或邮箱发自己一份

表格里是学号、姓名、模式、三轮的 d′/c、总 d′、总 c、准确率 —— 打分要用的都在。

### 路线 B（★ 最可靠）：让每位学生自己导出，班长汇总

这是项目里事先准备好的兜底，**完全不依赖教师后台**：

```
学生玩完 → 结果页点「导出成绩单」→ 下载到一个 CSV
        ↓
班长收齐 → 打包发给老师 → 老师用 Excel 打开
```

代价只是「要人工汇总一次」，成绩数据本身一个字都不少。
**所以：就算部署整个失败了，作业也照样能交。**

### 路线 C（懂命令行的人）：把数据库文件本身拷下来

全部成绩就完整地存在服务器上 `/data/sdt.db` 这一个文件里。
如果平台提供网页版的命令行（通常叫 `Shell` / `Console`），可以把那个文件下载下来存档
—— 这是最完整的备份（连学生每一轮的原始记录都在里面）。

### 为什么这么啰嗦

免费档的服务器随时可能因为平台调整、额度用完，或者你手滑点了一下「重新部署」，
就让成绩归零。

**收完就备份，才是真的存在。**
