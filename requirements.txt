# ★ 这个文件不是依赖清单本身，只是一个「路标」。
#
#   真正的、钉死版本的那份在 server/requirements.txt —— 要改依赖只改那一份。
#
# 【为什么要多这个文件】
#   云平台（Railway 用的 Railpack）判断「这个仓库是不是 Python 项目」的依据之一，
#   是【根目录】有没有 requirements.txt。而本项目的依赖清单放在 server/ 子目录里，
#   根目录什么都没有的话，平台会认不出这是 Python 项目 —— 构建直接失败，
#   而且报错信息不会直接告诉你原因。
#
# 【下面这行的意思】
#   pip 支持在一个 requirements 文件里「引入」另一个文件（嵌套引用），
#   路径是相对【本文件】解析的 —— 所以这行等于把 server/ 那份原样引进来。
#   已实测：从任意目录执行都能正确解析到 server/requirements.txt。
#
#   好处是依赖清单只有一份真源，不会两边版本写岔。
-r server/requirements.txt
