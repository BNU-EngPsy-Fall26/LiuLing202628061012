# 急诊分诊台（SDT Lab）

一个用「急诊分诊」包装的**信号检测论（Signal Detection Theory, SDT）教学实验**：
学生扮演分诊护士，在一批生命体征各异的患者里判断谁真的危重 —— 玩三轮，
然后在「概念实验室」里看着自己的 d′（辨别力）和 c（判据）被拆开讲。

技术栈一句话：**Python 3 + Flask + SQLite 做后端，原生 JavaScript 做前端，
没有框架、没有构建步骤、没有 npm** —— 打开就是能跑的网页。

---

## 学生怎么用

1. 打开老师给的网址（形如 `https://xxx.onrender.com/`）
2. 填**学号**和**姓名**（学号是成绩的唯一标识，同一个学号重复玩会覆盖上一次）
3. 看说明页，**二选一**：标准版（90 试次，约 15 分钟）或快速版（48 试次，约 9 分钟）
4. 先做一小段**练习轮**（不计分，熟悉操作），然后正式三轮
5. 三轮玩完 → 结果页 → **「导出成绩单」可以下载一个 CSV**（这是给部署出问题时的兜底，见下）

> 中途关掉网页也没关系 —— 重新打开、填同一个学号重玩一遍即可，
> 后端按学号覆盖，不会出现两条记录。

## 老师怎么进后台

- 网址 = **学生网址后面加 `/admin.html`**（例：`https://xxx.onrender.com/admin.html`）
- **口令**：不在代码里，也不在这个网页里 —— 部署的人设置了一个叫
  `SDT_ADMIN_PASSWORD` 的**环境变量**（见 [`docs/部署步骤.md`](docs/部署步骤.md) 第 4 步）。
  问部署这台服务的人要。
- 进去之后能看到全班每个人的三轮成绩明细，以及四张图：
  三轮 d′/c 对比、班级 ROC 散点、d′ 分布、实测 d′ vs 系统设定 d′。
- 右上角可以切换「全部 / 标准版 / 快速版」，下面四张图跟着一起变。
- **后台没有「一键导出」按钮**（没做）。要存档就：用鼠标把表格整张选中 →
  `Ctrl/Cmd + C` → 粘到 Excel 里。最保险的备份走学生端 CSV，见
  [`docs/部署步骤.md`](docs/部署步骤.md) 第 9 步。

> 口令连续输错不会锁账号，但也**不会**提示你「差在哪」—— 只说「口令错误」。
> 这是故意的：口令不能从错误提示里被猜出来。

## 本地怎么跑起来

```bash
cd server
pip3 install -r requirements.txt
python3 app.py                  # → http://127.0.0.1:5055
```

然后浏览器打开 <http://127.0.0.1:5055/>（学生端）和
<http://127.0.0.1:5055/admin.html>（教师端）。

- **端口是 5055，不是 5000** —— macOS 的「隔空播放接收器」常年占着 5000。
  要换端口：`SDT_PORT=8000 python3 app.py`
- **访问时用 `127.0.0.1`，别用 `localhost`** —— macOS 上 `localhost` 先解析到 `::1`，
  容易和别的回环服务撞车。
- **只有一个进程**：网页、静态资源（`/js/…`、`/styles/…`）和接口（`/api/…`）
  全在同一个端口出门，不用起第二个服务、不用反向代理。
- 数据库 `server/sdt.db` 第一次启动时自动建出来，**不进 git**。

本机开发时的默认教师口令是 `admin123`（代码里的默认值）。
**部署前必须用环境变量改掉**，否则任何看过源码的人都知道口令。

## 部署形态的三件必须知道的事

### ① `Procfile`（在**项目根目录**，不在 `server/` 里）

全文就一行：

```
web: gunicorn --chdir server app:app --bind 0.0.0.0:$PORT
```

逐段解释：

| 片段 | 为什么 |
|---|---|
| `web:` | 平台约定的进程类型名 —— 叫 `web` 的那个会被分配域名和 `$PORT` |
| `gunicorn` | 生产级 WSGI 服务器。Flask 自带的开发服务器**单线程、没加固**，官方明说不能用于生产 |
| `--chdir server` | 先切到 `server/` 再导入，这样 `app.py` 里的 `import db` 才找得到 |
| `app:app` | 从 `app.py` 里取出那个叫 `app` 的 Flask 实例（`模块:变量`） |
| `--bind 0.0.0.0:$PORT` | **关键**：`0.0.0.0` 才是「外面能连进来」（`127.0.0.1` 只有容器自己连得上）；`$PORT` 由平台动态分配，**不能写死** |

**★ 为什么这个文件必须放根目录、不能放进 `server/`：**

```
Procfile 放进 server/
        ↓
平台会把「项目根目录」认成 server/
        ↓
容器里可能只有 server/ 这一个目录
        ↓
app.py 里的 ROOT（= server/ 的上一层）指向不存在的地方
        ↓
index.html / js / styles 全部 404 —— 网页打开是一片空白
```

放根目录 + `--chdir server`，**整个仓库都在容器里**，静态伺服才找得到文件。

> 顺便：`gunicorn --chdir server` 意味着运行时的**工作目录**是 `server/`，
> 所以数据库的默认路径也落在 `server/sdt.db`。线上要改，见第 ③ 条。

### ② `server/app.py` 最后那行 `debug=True` 是安全的

```python
if __name__ == '__main__':
    app.run(host='127.0.0.1', port=PORT, debug=True)
```

**这段只在 `python3 app.py`（本地开发）时执行。** gunicorn 是 `import app`，
`__name__` 不等于 `'__main__'`，**根本不跑这段** ——
所以线上 `debug` 是关的、`host` 由 gunicorn 的 `--bind` 决定。

看到 `debug=True` 不用惊慌，**也别删**：本地开发要靠它自动重载。

### ③ 环境变量

| 变量 | 部署时该设成 | 说明 |
|---|---|---|
| `SDT_ADMIN_PASSWORD` | 一个只有老师知道的口令 | **不设的话就是源码里的 `admin123`**，等于没锁 |
| `SDT_DB_PATH` | `/data/sdt.db` | 数据库文件放哪。`/data` 是挂持久磁盘的地方 —— **不设的话数据库写在容器里，重新部署就没了**（见下） |
| `SDT_PORT` | **不用设** | 线上端口由 `$PORT` 决定；这个变量只管本地 `python3 app.py` |

### ★ ④ SQLite 的持久化陷阱（重要，别跳过）

容器的文件系统是**临时**的：

```
重新部署一次 → 容器重建 → 容器里的数据库文件没了 → 全班成绩消失
```

对作业场景这是致命的（学生在几天里陆续交，中途重新部署一次全没了）。
所以必须把数据库放到**持久磁盘（Volume）**上：

```
平台的「持久磁盘 / Volume」功能 → 挂到 /data
        ↓
环境变量 SDT_DB_PATH=/data/sdt.db
        ↓
数据库落在持久盘上，重新部署也不丢
```

**免费档往往不支持持久磁盘。** 遇到这种情况有四条路，按推荐顺序：

1. **换一个支持持久磁盘的平台**（哪怕是几块钱一个月的最低档）
2. **中途绝不重新部署**：代码冻结，只在实验开始前部署一次
3. **只在实验当天部署**，收完数据立刻按
   [`docs/部署步骤.md`](docs/部署步骤.md) 第 9 步把成绩备份下来，再关掉服务
4. **不上线**：让学生用本地跑起来的那份（或老师自己的笔记本当服务器），
   结果页导出 CSV 汇总

第 2、3 条的要害是：**只要收完数据就备份，就算服务明天没了，成绩还在你手上。**

## 目录结构

```
sdt-lab/
├── Procfile                 ← ★ 必须在根目录，见上
├── README.md                ← 本文件
├── CONTRACT.md              ← 设计契约（内部文档，线上 404）
├── index.html               ← 学生端（登录/说明/游戏/结果/实验室，一个页面切屏）
├── admin.html               ← 教师端
├── js/                      ← 前端全部逻辑（原生 JS，无构建）
├── styles/                  ← 样式（CSS 变量定义在 tokens.css）
├── server/                  ← 后端：app.py（路由）/ db.py（SQLite）/ requirements.txt
├── docs/                    ← 给人和给老师看的文档（线上 404）
└── tasks/                   ← 施工任务书（线上 404）
```

## 安全上的四条约定（改后端前先读）

1. 教师口令只从环境变量读，**前端任何文件里都没有明文口令**。
2. 后台 token 只存在进程内存里（`VALID_TOKENS`），重启即失效 —— 作业场景够用。
3. 口令错误只回「口令错误」，不回显任何与口令有关的信息。
4. **静态文件走白名单**：只放行 `index.html`、`admin.html`、`js/`、`styles/`。
   其余一律 404 —— 包括 `server/`（后端源码和**数据库**）、`CONTRACT.md`、
   `docs/`、`tasks/`、任何以 `.` 开头的路径。
   线上部署完后**必须重新验一遍**（`docs/部署步骤.md` 第 7 步的第 7~9 条）。

## 自测（本地跑一遍"生产模式"）

在做任何平台操作之前，先确认**应用本身**是可部署的：

```bash
cd ~/Documents/工程心理学作业/sdt-lab
pip3 install -r server/requirements.txt
SDT_ADMIN_PASSWORD=test123 SDT_DB_PATH=/tmp/prod-test.db \
  python3 -m gunicorn --chdir server app:app --bind 0.0.0.0:5056
```

另开一个终端：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5056/            # 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5056/admin.html  # 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5056/server/app.py  # 404
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5056/server/sdt.db  # 404
curl -s -X POST http://127.0.0.1:5056/api/admin/login \
  -H 'Content-Type: application/json' -d '{"password":"test123"}'          # ok:true
```

**想确认这几条真的在测东西**：把 `--chdir server` 删掉（改成 `--chdir .`），
gunicorn 会因为 `No module named 'app'` **起不来**，上面五条全红 ——
说明它们验的确实是「这条命令能不能在生产服务器上把应用拉起来」。
