## 一、画成什么样

```
┌────────────────────────────────────────────────────────┐
│  ┌──────────────────────────────────────────────┐      │
│  │  ●           ╱╲                              │      │  ← 报警灯（左上角小圆点）
│  │             ╱  ╲    ╱╲                       │      │
│  │  ──────────╯    ╲__╱  ╲______──────────────  │      │  ← ECG 波形（青绿发光，向左滚动）
│  │                                              │      │
│  │   心率          血氧          血压            │      │
│  │    118           93           96/62          │      │  ← 大号等宽数字
│  │    bpm           %            mmHg           │      │
│  └──────────────────────────────────────────────┘      │
└────────────────────────────────────────────────────────┘
```

**面板本身**：比卡片更深的底色（`--c-bg` 再暗一点，或直接用 `#080D12`），

**高度控制在 160~200px**（小屏 130~160px）—— 别把页面撑爆。

## 二、四个组件

### ① ECG 波形（核心）

**用 Canvas 画**，一条**向左滚动**的心电线。

**这不是正弦波。** 心电波形长这样：

```
      R
      ╱╲
     ╱  ╲
    ╱    ╲
───╯      ╲___________╱──────  ← 每个心动周期一个 QRS 复合波 + T 波
   Q      S          T
```

**一个心动周期的形状**（横轴 = 周期内的相位 0~1）：

| 相位 | 形状 |
|---|---|
| 0.00 ~ 0.10 | 基线（平） |
| 0.10 ~ 0.15 | **P 波**：一个小凸起（高度约 0.15） |
| 0.15 ~ 0.28 | 回到基线 |
| 0.28 ~ 0.32 | **Q 波**：向下一个小凹陷（-0.15） |
| 0.32 ~ 0.38 | **R 波**：**向上一个大尖峰（+1.0）** ← 最显眼的那一竖 |
| 0.38 ~ 0.44 | **S 波**：向下一个大凹陷（-0.35） |
| 0.44 ~ 0.62 | 回到基线 |
| 0.62 ~ 0.78 | **T 波**：一个较宽较缓的凸起（高度约 0.3） |
| 0.78 ~ 1.00 | 基线 |

**每个周期占的宽度 = 60 / 心率 秒**（心率 72 → 每 0.83 秒一个周期）。

**滚动的实现**：

```js
// 每次 requestAnimationFrame：
//   用 performance.now() 算【从开始到现在过了多少秒】
//   相位偏移 = 已过秒数 / 周期秒数
//   整条线整体向左平移相应距离
// ★ 用【真实时间】算，不要用帧计数 —— 否则不同刷新率的设备速度不一样
```

### ② 数字读数

**必须和患者卡片上的体征【完全一致】** —— 用同一个 `patient.vitals`，
**不要自己另算一遍**。

```
心率   118      ← patient.vitals.hr
血氧    93      ← patient.vitals.spo2
血压  96/62     ← patient.vitals.sbp / dbp
```

- 数字用 **`--font-mono`**（等宽），**大号**（约 2rem）
- 单位（bpm / % / mmHg）小一号，用 `--c-text-dim`
- **数字颜色按契约 2.4 的分档规则**（和体征那一行用同一套阈值和颜色）

**★ 这一条是硬要求**：面板上的 118 和卡片上的 118 必须是同一个数。
如果对不上，玩家会以为是两个东西。

### ③ 报警灯

左上角一个小圆点，**颜色和闪烁速度都由 severity 决定**：

| severity | 颜色 | 闪烁 |
|---|---|---|
| < 0.4 | `--c-normal`（绿） | **常亮，不闪** |
| 0.4 ~ 1.1 | `--c-watch`（黄） | 慢闪（约 1 秒一次） |
| > 1.1 | `--c-danger`（红） | 快闪（约 0.5 秒一次） |

**用 CSS 动画**（改 `opacity` 或 `box-shadow`），**不要用 JS 定时器**。

**分档边界和 `patient-data.js` 里的 `tierRules.bounds` 保持一致**（0.4 / 1.1）。

### ④ 光晕

整块面板要有**微弱的发光感**：

```css
/* 波形线 */
box-shadow: 0 0 6px var(--c-accent), 0 0 14px rgba(46,211,166,.35);
/* 报警灯 */
box-shadow: 0 0 8px currentColor, 0 0 18px currentColor;
```

**光晕是这个设计的灵魂** —— 深色底 + 发光线条 = 真实监护仪的观感。
**别省这一步。**

## 三、数据来源与铁律

**唯一的数据源是 `severity`**（以及从它算出来的 `patient.vitals`）。

```
✅ 允许：根据 severity / vitals 决定波形密度、灯的颜色、闪烁速度
❌ 禁止：任何形式的 if (patient.hasSignal)
❌ 禁止：把 hasSignal 写进 DOM、data-*、class、title
❌ 禁止：console.log 打印 patient
```

**契约第 8 节的铁律一条都没变。**

### ★ 波形的心率，用哪个数

**用 `patient.vitals.hr`，不要自己从 severity 再算一遍。**

理由：如果自己算，万一两处公式不一致，**面板显示 118、卡片显示 116** ——
玩家会以为哪里出错了。

## 四、接口

```js
// js/monitor.js
window.Monitor = {
  // 渲染/更新这块面板。同一局里每换一位患者调一次。
  //   el:       容器（#monitorPanel）
  //   patient:  见契约 4.1
  //   opts.frozen: true 时【画在固定相位、不做动画】（见下，测试要用）
  render: function (el, patient, opts) { ... },

  // 停掉动画（离开游戏屏、或者重新渲染前调用，避免多个循环同时跑）
  stop: function () { ... },
};
```

### ★ `frozen` 参数是给测试用的，必须实现

**问题**：波形一直在动，那契约里那条铁律自查会永远失败——

> 把 `hasSignal` 从 `true` 改成 `false`，**判断态的 DOM 必须一字不差**

**两次渲染的时间点不同，Canvas 像素就不同** —— 不是因为泄题，是因为动画。

**所以**：`frozen: true` 时，波形画在**固定的相位（t = 0）**，不启动 `requestAnimationFrame`。

**平时是动画的，测试时冻结。**

## 六、自测（★ 按契约 §10 格式，每条都要写"怎么确认它真的会失败"）

### ① ★ 铁律没破

**【测什么】** 把 `hasSignal` 从 true 改成 false，判断态**整屏 DOM 一字不差**
**【怎么测】** `frozen: true` 渲染两次，比较 `outerHTML`（Canvas 部分比 `toDataURL()`）
**【它怎么失败】** 有人按 `hasSignal` 改了波形密度、灯色、数字
**【★ 怎么确认它真的会失败】** 临时加一行 `if (hasSignal) 灯变蓝` —— 断言必须红

### ② ★ 波形真的在动

**【测什么】** 波形不是静态图
**【怎么测】** `frozen: false` 渲染后，等 300ms 再取一次 `canvas.toDataURL()`，两次**必须不同**
**【它怎么失败】** 忘了 `requestAnimationFrame`、或者每帧画的内容一样
**【★ 怎么确认它真的会失败】** 把动画循环注释掉（只画一帧）—— 断言必须红

**（这条是"动画"类断言的典型陷阱 —— 具体的坑见下）**

### ③ ★ 灯真的在闪

**【测什么】** severity 落在中间档和危险档时，灯的 `opacity` 会周期变化
**【怎么测】** 采样 `getComputedStyle(el).opacity` 若干次，**不能全相等**
**【它怎么失败】** CSS 动画名写错、或者 `animation` 属性被别的规则覆盖
**【★ 怎么确认它真的会失败】** 把 `animation: none` 加上 —— 断言必须红

### ④ ★ 面板数字和卡片数字一致

**【测什么】** 面板上的心率 = 卡片上的心率 = `patient.vitals.hr`
**【怎么测】** 对 20 位随机患者逐个比对三处
**【它怎么失败】** 面板自己另算了一遍心率
**【★ 怎么确认它真的会失败】** 把面板的心率改成 `hr + 1` —— 必须红

### ⑤ 删掉立绘，实验照样跑

**【测什么】** 这一块是纯增量，不影响核心
**【怎么测】** 把 `#monitorPanel` 从 DOM 里删掉（或者不调 `Monitor.render`），
完整玩一局 → **必须照样能走到结果页**
**【它怎么失败】** 有人把 `Monitor.render` 的返回值用在了后面的逻辑里
**【★ 怎么确认它真的会失败】** 这条是"负对照"，本身就是红的方向
（你要证明的是"删掉它不会坏"，所以**跑通就是证据**）

### ⑥ 布局没被改坏

**【测什么】** 加了面板之后，患者卡片里那行生命体征**还是不会上下跳**
**【怎么测】** 连着渲染 20 位随机患者，收集体征行的 `getBoundingClientRect().top`
**【期望】** 只有 1 个不同的值
**【它怎么失败】** 面板高度随内容变化（比如波形 canvas 高度没定死）
**【★ 怎么确认它真的会失败】** 把 canvas 的高度改成 `auto` —— 断言必须红
**【⚠️ 环境提醒】** **这条不能用 jsdom 跑**（它不渲染，`getBoundingClientRect` 恒返回 0）。
**必须用真浏览器**（headless Chrome 或真 Chrome），否则测的是空气。

### ⑦ 窄屏不撑爆

**【测什么】** 400px 宽度下，面板不溢出、页面没有横向滚动条
**【怎么测】** 真浏览器 400px 视口，量 `scrollWidth` vs `clientWidth`
