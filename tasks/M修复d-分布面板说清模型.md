## 一、玩家反馈了什么

> 在实验室两个分布下的文案：「横轴是判定标准 c 的尺子：噪音分布在 −d′/2、
> 信号分布在 +d′/2，两峰相距 d′。」
>
> **这个应该放在这里吗？噪音分布、信号分布、两峰相聚在 SDT 理论中是固定不变的吗？
> 这是标准状态下的吧？在这个网站里应该随着玩家自己的数据变化吧？**

**他的疑问里有一处理解错了，但他指出的问题是真的。**

### ① 理解上的岔路（不用改代码，但你要知道）

```
标准 SDT 模型：噪音 N(0,1)、信号 N(d′,1)
        ↓
「两峰相距」和 d′ 是【同一个东西】—— 不是观察到的，是定义出来的
        ↓
而且面板上【有 d′ 滑块（0~4）】，拖它就变 —— 它不是固定的
```

### ② 真问题之一：**那句话是同义反复**

```js
var dn = Utils.npdf(x, -d / 2, 1);   // 噪音峰在 −d′/2
var ds = Utils.npdf(x,  d / 2, 1);   // 信号峰在 +d′/2
```

```
峰定义在 ∓d′/2  →  相距 = (+d′/2) − (−d′/2) = d′
        ↓
文字说「两峰相距 d′」=「d′ 相距 d′」
```

**它读起来像信息，其实什么都没说。**

### ③ 真问题之二：**面板没说"这是模型"，也没和玩家的数据连起来**

```
两个分布面板  →  完全不读 Store        ← 纯理论模型
ROC 面板      →  读 Store.rounds        ← 玩家自己的三个工作点
```

**这个分工是契约定的、没问题。但页面上没有一个字说明** ——
所以玩家会以为这一屏在展示某个"标准状态"。

**而且它离玩家最近的机会被浪费了**：玩家刚玩完，他自己实测的 d′ 就在
`Store.rounds` 里躺着，**面板却完全不提**。

## 二、改成什么

### 位置

`js/lab/dist.js` 第 145 行附近，现在是：

```js
'    横轴是判定标准 c 的尺子：噪音分布在 −d′/2、信号分布在 +d′/2，两峰相距 d′。',
```

### 改成三段

```
横轴是判定标准 c 的尺子。
这是理论模型：两条曲线的横向间距就是 d′ —— 拖上面的滑块就能看到它变。
```

**★ 删掉 `−d′/2` / `+d′/2`。** 那是**实现细节** —— 选这个刻度只是为了让判定线
恰好落在 `x = c`、让 `β = exp(c·d′)` 干净。**玩家不需要知道。**

**★ 不说「两峰相距 d′」** —— 换成「横向间距就是 d′」，**并且说清它是可拖的**。

### 再加一段：连回玩家自己的数据

**读过 `Store.rounds` 之后**（结构见契约 4.3，`metrics.dPrime`）：

**玩过（`Store.rounds.length > 0`）**：

```
你上一局的 d′：  [ 第一轮 1.56 ]  [ 第二轮 1.59 ]  [ 第三轮 0.00 ]
                 点一下就把滑块跳到那个值
```

**三个按钮，点了就把 d′ 滑块设成那个值、重画。**
按钮上的数字用 `Utils.round1` 或 `toFixed(2)` —— **和结果页的格式保持一致**。

**没玩过（`Store.rounds` 为空）**：

```
玩完三轮再回来看，这里会标出你自己实测的 d′。
```

### ★ 边界情况：实测 d′ 超出滑块范围

**滑块是 0~4，但实测 d′ 可能是负的**（pH < pFA 时，比如 `-0.31`）。

**必须处理**：夹到 `[0, 4]` 之间，**并且说明**：

```
你的第三轮实测 d′ 是 −0.31，超出了滑块范围（0 ~ 4），已夹到最左边。
```

**这条不处理的话，点了按钮滑块不动，玩家会以为按钮坏了。**

## 四、自测（★ 按 §10 六字段）

### ① 那句话里没有废话、没有实现细节

**【测什么】** 渲染出来的文字里没有 `−d′/2`、`+d′/2`、`两峰相距`
**【怎么测】** 抓 `textContent`，搜这三个子串
**【它怎么失败】** 只改了半句、留了另一半
**【★ 怎么确认它真的会失败】** 把 `−d′/2` 加回字符串里，断言必须红

### ② 「这是理论模型」这句在

**【测什么】** 文案里出现了"理论模型"或等价的说明
**【★ 怎么确认它真的会失败】** 删掉那半句，断言必须红

### ③ 三个按钮反映的是真数据

**【测什么】** 塞三组已知的 `Store.rounds`（比如 1.56 / 1.59 / 0.00），
按钮上的数字必须和 `metrics.dPrime` 一致
**【怎么测】** 逐个比对按钮文字和 Store 里的值
**【它怎么失败】** 读错字段名、或读的是 `overall` 而不是三轮各自的
**【★ 怎么确认它真的会失败】** 把按钮文字改成固定值，断言必须红

### ④ 点按钮真的把滑块挪过去了

**【测什么】** 点「第二轮」之后，d′ 滑块的值 = 1.59，**而且图重画了**
**【怎么测】** 读滑块的 `value`，再读 ECharts option 里那两条曲线（峰的位置应随之变）
**【它怎么失败】** 按钮改了 `state.d` 但没重画；或者只改滑块 DOM 没改 state
**【★ 怎么确认它真的会失败】** 把重画那一步注释掉，断言必须红

### ⑤ 超范围的兜底

**【测什么】** 塞一组含负数 d′ 的数据（`-0.31`），点它 → 滑块夹到 0，
**页面上有一句说明**
**【★ 怎么确认它真的会失败】** 去掉夹取，滑块会接受负值或不动 —— 断言必须红

### ⑥ 没玩过时不报错

**【测什么】** `Store.rounds` 为空时，显示提示句，**控制台 0 红字**
**【★ 怎么确认它真的会失败】** 把空数组的判断删掉，取 `rounds[0].metrics` 会抛错 —— 必须红

### ⑦ ★ 回归：图、滑块、数字一个字没变

**【测什么】** 默认值（d′=1.5, c=0）下，混淆矩阵四格、β、A′、曲线采样点数
**和改动前完全一致**
**【怎么测】** 和上一波同样的硬比对（H=0.773 / FA=0.227 / β=1.00 / A′=0.85、
241 个采样点、红填充只在判定线右侧）
**【为什么重要】** 这次改的是"说明文字"，**但那段文字就在 `render()` 里** ——
很容易顺手碰到旁边的逻辑
**【★ 怎么确认它真的会失败】** 改一处 `npdf` 的参数（比如 `-d/2` 改 `-d/3`），
这些数值断言必须红
