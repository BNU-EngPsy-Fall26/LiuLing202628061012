## ① `js/patient.js`：意识的分档阈值 ★ 最重要

### 改什么

在 `generate()` 里，现在是：

```js
意识 = severity < -0.5 ? '清醒'
     : severity <  0.5 ? '嗜睡'
     : severity <  1.5 ? '昏睡'
     :                   '昏迷'
```

**改成**：

```js
意识 = severity <  0.8 ? '清醒'
     : severity <  1.5 ? '嗜睡'
     : severity <  2.5 ? '昏睡'
     :                   '昏迷'
```

**只改这三个数字。** 契约 3.3 已经更新，并把「为什么改」写在那一节了 —— **照抄那份理由进代码注释。**

### 为什么（一句话版，写进注释）

```
旧阈值下，"其实不需要紧急处理"的患者里有 31.1% 显示成昏睡或昏迷
        ↓
医学上荒谬（昏睡/昏迷按定义就是急危重症）
而且这条线索几乎没用（只看它，正确率 57.6%，瞎猜 50%）
```

### 验证

**【测什么】** 各档在噪音组 / 信号组里的占比

**【期望】**（我独立算过，容差 ±2%）

```
           噪音组    信号组
清醒       87.1%    16.1%
嗜睡       11.2%    33.9%
昏睡        1.7%    42.1%
昏迷       0.02%     7.9%

★ 其实没事的患者里显示昏睡+：约 1.7%（旧的是 31.1%）
```

**【★ 怎么确认它真的会失败】** 把阈值改回 −0.5/0.5/1.5 → "2% 以内"那条断言必须红。

### ★ 顺带验证：报警灯也跟着正常了

**别改灯的逻辑**（它刚改好，取五项里最差那档）。**改了意识阈值之后，灯的分布会自己变**：

```
                  绿 / 黄 / 红
改之前（旧阈值）：  6.3% / 32.9% / 60.8%    ← 红压倒性，灯没用
改之后（新阈值）： 39.9% / 28.4% / 31.6%    ← 三档均衡
```

**【测什么】** 500 位随机患者的灯色分布
**【期望】** 三档都在 20%~45% 之间（**不是**某档超过 50%）
**【★ 怎么确认它真的会失败】** 新断言"没有哪一档超过 50%"在旧阈值下必然红。

## ③ `index.html`：开发导航条加 `?dev=1` 门控

### 问题

`.dev-nav` 是**常显**的。**学生一打开就看见「7 后台」那个按钮。**

契约第 9 节第 1 条就是这条：

> - [ ] **开发导航条必须藏起来或删掉**
>       它上面有「7 后台」按钮，学生一打开就看见"后台"两个字。

### 改法

**用 CSS 默认藏起来，只有 `?dev=1` 时才显示**（比用 JS 改 `style` 更稳 —— 不会闪一下）：

```css
/* main.css */
.dev-nav { display: none; }
html.dev-mode .dev-nav { display: flex; }
```

```js
/* index.html 的 inline script 开头 */
if (new URLSearchParams(location.search).has('dev')) {
  document.documentElement.classList.add('dev-mode');
}
```

**★ 门控必须【在页面渲染之前】生效** —— 放在 `<head>` 之后的第一个 `<script>` 里，
或者用上面的 CSS 方案（CSS 方案天然满足，推荐）。

**【测什么】** 不带参数打开 → 导航条**不可见**；带 `?dev=1` → 可见
**【怎么测】** 真浏览器里读 `.dev-nav` 的 `getComputedStyle().display`
**【★ 怎么确认它真的会失败】** 把 CSS 那条 `display:none` 去掉 → 断言必须红

## ⑤ `admin.html` + `js/admin.js`：加「导出全班 CSV」

### 为什么要加

M15 报告里发现：**教师后台没有任何导出功能**。

现在老师的备份路线是"把表格整张选中、粘进 Excel" —— 能用，但很笨，
而且**一旦平台把容器重建（SQLite 没挂持久盘的话），数据就没了**。

**一个导出按钮是"不依赖运维"的退路。**

### 怎么做

在工具栏（`[全部][标准版][快速版] [刷新数据] [退出登录]`）加一个：

```
[ 导出全班 CSV ]
```

点了之后：

1. 拿**当前筛选后的** rows（和表格里显示的一致 —— 老师筛了"快速版"就该只导出快速版）
2. 生成 CSV
3. 触发下载，文件名带上日期：`sdt-全班-2026-10-08.csv`

**列**（和表格一致）：

```
学号,姓名,模式,第一轮d′,第一轮c,第一轮准确率%,第二轮d′,第二轮c,第二轮准确率%,第三轮d′,第三轮c,第三轮准确率%,总d′,总c,总准确率%,提交时间
```

**要求**（照抄 `js/submit.js` 里 `exportCsv` 的做法）：

- **开头加 UTF-8 BOM**（`﻿`）—— **不加的话 Excel 打开中文是乱码**
- 换行用 `\r\n`
- 用 `Blob` + `URL.createObjectURL` + `<a download>` 触发下载
- **★ 下载前必须 `document.body.appendChild(a)`**，否则某些浏览器点了不下载

**rows 为空时**：按钮置灰或点了给一句提示，**不要下载一个只有表头的空文件**。

### 顺手更新文档

`docs/部署步骤.md` 里现在写的备份路线是"选中表格粘进 Excel"和"让学生交 CSV"。
**改成**：

```
老师备份：教师后台点「导出全班 CSV」→ 下载一个文件
（在这之前：让学生各自在结果页点「导出成绩单」，那是最后一道保险）
```

**【★ 怎么确认它真的会失败】** 去掉 BOM → 断言"前三个字节是 EF BB BF"必须红；
去掉 `appendChild` → 断言"点击发生在挂进 DOM 之后"必须红。
