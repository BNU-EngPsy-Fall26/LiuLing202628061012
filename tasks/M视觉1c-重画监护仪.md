## 二、★ 加方格网格 —— 这是"像不像"的最大杠杆

**人对监护仪的记忆，很大程度就是那片绿格子。没有它，画得再准也只是折线图。**

两条波形各自的格子里画网格：

```css
/* 小格：细、暗 */
background-image:
  repeating-linear-gradient(0deg,  var(--c-border) 0 1px, transparent 1px 12px),
  repeating-linear-gradient(90deg, var(--c-border) 0 1px, transparent 1px 12px);
/* 大格：稍亮、每 5 小格一条 */
background-image:
  repeating-linear-gradient(0deg,  rgba(36,49,63,.85) 0 1px, transparent 1px 60px),
  repeating-linear-gradient(90deg, rgba(36,49,63,.85) 0 1px, transparent 1px 60px);
```

**要求**：
- 网格要**看得见但很暗** —— 它是背景，不能抢波形
- **绝对不要用亮色**（真监护仪的格子是暗绿的，不是白的）
- 用 CSS 的 `background-image` 实现，**不要用 Canvas 画格线**（Canvas 用来画波形）

## 三、★ 波形形态要随 severity 变 —— 直接回应"都差不多"

**光靠密度区分不够（只有 1.36 倍）。但【形态】能差很多，而且是真实的：**

| severity | 节律 | 视觉 |
|---|---|---|
| **< 0.4** | **规整窦性** | R-R 间隔基本均匀（±5% 以内） |
| **0.4 ~ 1.1** | **偶发早搏** | 约每 8~12 拍出现一个**宽大畸形**的早搏波 |
| **> 1.1** | **明显不齐** | R-R 间隔 **±30%** 抖动，且早搏更频繁（每 4~6 拍一个） |

**真实临床就是这样：危重病人的心电图不是"跳得快一点"，而是形状不对了。**

### 早搏波长什么样

```
正常拍：   ──╱╲──          （窄、高、干净）
早搏拍：   ─╱‾‾╲───        （宽 1.6 倍、矮 0.6 倍、没有 P 波）
                    ↑ 紧跟着一个【较长的代偿间歇】
```

### ★ 心搏序列怎么生成 —— 用 `patient.id` 当种子

**不要引入新的随机数来源。** 做法：

```js
// 用 patient.id（形如 "P-0423"）做一个简单的字符串哈希当种子
// 生成一串固定的 R-R 间隔和"哪几拍是早搏"
// 同一位患者 → 永远得到同一串心搏（可复现，重渲染也一致）
```

**为什么这样**：
- 不需要 `opts.rng`（接口不用改）
- 同一位患者**重渲染时波形一致**（否则 `frozen` 那套自测会不稳）
- **完全不引入新的随机性** —— 铁律那套照旧成立

**★ 铁律**：心搏序列**只由 `severity`（以及从它来的 `vitals.hr`）和 `patient.id` 决定**，
**不许读 `hasSignal`**。

## 四、第二条波形：血氧（体积描记波）

**它的形状和心电完全不同，是圆润的脉冲：**

```
     ╱‾╲
    ╱   ╲___
   ╱        ╲
  ╱          ╲___
 ╱               ╲___
```

**要求**：
- **主峰 + 一个"切迹"**（主峰下来之后有个小台阶，再落下去）—— 这是它的特征
- **圆润**，不要有尖角（和心电的尖锐 QRS 形成对比）
- **密度跟心率走**（脉搏和心搏同步，真实如此）
- **幅度基本恒定**（真实血氧波形不会因为血氧低就变小）
- **颜色**：用 `--c-primary`（青）还是别的？**你定，但两条波形要一眼分得开**（现在心电是 `--c-accent` 青绿）

**★ 血氧波形不参与"形态随 severity 变"** —— 只有心电那一条有节律变化。
血氧只跟心率的密度。**别给它也加早搏**，那不真实。

## 七、自测（★ 按 §10 六字段）

### ① ★ 形态真的随 severity 变了（这条是本次的核心）

**【测什么】** 在**心率相同**的前提下，三档 severity 的**波形形态不同**

**【怎么测】** 造三位患者，**把 `vitals.hr` 人为设成同一个值（比如都是 80）**，
只让 `severity` 分别是 `−1 / 0.7 / 2`（对应三档）。渲染后比 `canvas.toDataURL()` 的**全串摘要**。

**【期望】** 三个互不相同；而且能进一步量出：
- `−1` 那位的 R-R 间隔**方差最小**
- `2` 那位**方差最大**

**【它怎么失败】** 只改了密度没改形态 —— 那样 hr 相同时三条会**完全一样**

**【★ 怎么确认它真的会失败】** 把形态逻辑关掉（所有 severity 都画规整窦性）→
**"三个摘要互不相同"这条必须红**（三条会一模一样）

> **这条测试的关键是"把 hr 设成同一个值"** —— 否则你分不清"不同"是因为密度还是因为形态。
> **务必照做。**

### ② 网格真的画出来了

**【测什么】** 波形区的网格是 CSS 背景，不是一张空白
**【怎么测】** 真浏览器里读 `getComputedStyle(波形容器).backgroundImage`，应该含 `repeating-linear-gradient`
**【★ 怎么确认它真的会失败】** 把 `background-image` 注释掉 → 必须红

### ③ 两条波形真的不同

**【测什么】** 心电和血氧不是同一条曲线
**【怎么测】** 两条 canvas 各自 `toDataURL()`，**必须不同**；
另外量血氧那条的**尖峰数**应该明显少于心电（它是圆润脉冲，不是每个拐点都算）
**【★ 怎么确认它真的会失败】** 让血氧那条复用 ECG 的绘制函数 → 必须红

### ④ 上一波那几条全部照旧

**【测什么】** 你上一波验过的，现在还是对的
**【怎么测】** 重跑 `/tmp/mon/` 里那两套脚手架
**【必须全绿的】**：
- 铁律自查（翻 hasSignal，`frozen:true` 下 DOM + canvas 像素一字不差）
- 波形在动（三帧摘要不同）
- 灯在闪（三档，慢闪 1s / 快闪 0.5s）
- 面板数字 = 卡片数字（20 位 + 36 例数值扫描）
- 灯 = 卡片最差那格的颜色（54 例）
- **布局不跳**（20 位患者的 `.vitals-row` top 只有一个值）← 真浏览器
- **窄屏不溢出**（400px，`scrollWidth ≤ clientWidth`）
- 删掉面板照样能跑完一局

**【★ 怎么确认它真的会失败】** 用上一波那几个变异（`alarm-leak` / `no-anim` / `no-blink` /
`hr-off-by-1` / `jumpy-canvas`）各跑一次，确认它们**仍然会红** ——
证明这些断言在新代码里**还没失效**。

### ⑤ 心率差异仍然看得出来（在极端情况下）

**【测什么】** 心率 45 和 140 的波形，密度明显不同
**【怎么测】** 造两位患者，hr 分别 45 / 140，数"屏幕宽度内的心搏数"
**【期望】** 140 那位的搏数**至少是 45 那位的 2.5 倍**
**【★ 怎么确认它真的会失败】** 把 `state.bps` 写死成 1.2 → 必须红
