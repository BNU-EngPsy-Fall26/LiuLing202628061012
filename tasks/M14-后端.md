## 接口（契约 6.1，照着实现）

| 方法 | 路径 | 入参 | 返回 |
|---|---|---|---|
| POST | `/api/login` | `{ studentId, name }` | `{ ok, student:{id,name} }` |
| POST | `/api/submit` | 一个 Session | `{ ok }` |
| POST | `/api/admin/login` | `{ password }` | `{ ok, token }` |
| GET | `/api/admin/results` | `?mode=all\|standard\|quick` | `{ ok, rows:[] }` |
| GET | `/api/admin/summary` | `?mode=...` | `{ ok, summary:{...} }` |

**响应格式统一 `{ ok, msg?, ... }`，失败用 400 / 401 / 500。**
`msg` 用**中文**（老师会看到）。

## 硬性要求

### 1. 重名覆盖，不是新增

同一个 `studentId` 重复提交时**更新那一行**，不要插两条。
学生可能玩两遍，教师后台不该看到重复。

```sql
INSERT INTO results (...) VALUES (...)
ON CONFLICT(student_id) DO UPDATE SET
  ...
```

### 2. 教师口令从环境变量读，**不许写死在代码里**

```python
import os
ADMIN_PASSWORD = os.environ.get('SDT_ADMIN_PASSWORD', 'admin123')   # 默认值仅用于本地开发
```

**默认值要写得显眼**（比如叫 `admin123`），并在 README 里提醒：
**部署前必须改成环境变量。**

同时在 `/api/admin/login` 里：口令错了就 401，**不要泄露"口令是什么"**。

### 3. token 只放内存

```python
import secrets
VALID_TOKENS = set()          # 进程重启就失效，够用
```

`/api/admin/login` 成功时 `secrets.token_hex(16)` 生成，加进集合。
其他 `/api/admin/*` 用 `Authorization: Bearer <token>` 校验。

（作业场景不需要持久化 token。）

### 4. `/api/submit` 的字段校验

`studentId` / `mode` / `rounds` 缺一个 → 400 + 中文提示。
`mode` 只能是 `standard` 或 `quick`，否则 400。

### 5. `/api/admin/summary` 的返回值

严格按契约 6.1 那个结构。**特别要注意 `rounds` 那一段** ——
教师后台要靠它画"三轮 d′ 不变、c 在动"那张图，它是这个项目最有教学价值的图。

`mean` / `sd` 用 Python 的 `statistics.mean` / `statistics.stdev`。
**样本数小于 2 时 `sd` 返回 0**，不要抛异常。

### 6. CORS

开发时前端可能是从 `file://` 打开的，或者从别的端口。
用 `flask_cors.CORS(app)` 全放开就行（作业场景，不做生产级安全）。

## `js/submit.js` —— 前端调接口那一层

```js
window.Submit = {
  // POST /api/submit。★ 失败不许抛错、不许弹窗 —— 后端挂了学生照样要能玩完
  send: function (session) { ... },

  // 把 Session 存进 localStorage（后端没通时的兜底）
  save: function (session) { ... },

  // 导出 CSV（老师要是不用后端，可以让学生交这个文件）
  exportCsv: function (session) { ... },
};
```

**`send()` 必须写成"发出去就不管了"**：

```js
fetch('/api/submit', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(session)
}).catch(function () { /* 静默失败 */ });
```

参考站就是这么做的 —— 见契约 6.1 的说明。

**`exportCsv()`** 生成一个 CSV 字符串，用 `Blob` + `URL.createObjectURL`
触发下载。列：学号、姓名、模式、三轮各自的 d′/c/准确率、合并的 d′/c/准确率。

## 自测（用 curl，不用等前端）

启动服务：

```bash
cd ~/Documents/工程心理学作业/sdt-lab/server
pip3 install flask flask-cors
python3 app.py          # 默认 5000 端口
```

另开一个终端，逐条验：

```bash
# 1. 学生登录
curl -s -X POST localhost:5000/api/login \
  -H 'Content-Type: application/json' \
  -d '{"studentId":"2026280001","name":"张三"}'

# 2. 提交一份成绩（自己按契约 4.4 编一个 Session）
curl -s -X POST localhost:5000/api/submit \
  -H 'Content-Type: application/json' \
  -d '{"studentId":"2026280001","studentName":"张三","mode":"standard", ...}'

# 3. 再提交一次同一个学号 —— 必须【覆盖】而不是新增
#    提交后查数据库确认只有一行：
sqlite3 server/sdt.db "SELECT student_id, mode, r1_dprime FROM results;"

# 4. 教师登录拿 token
curl -s -X POST localhost:5000/api/admin/login \
  -H 'Content-Type: application/json' -d '{"password":"admin123"}'

# 5. 没带 token 访问管理接口 —— 必须 401
curl -s -o /dev/null -w '%{http_code}\n' localhost:5000/api/admin/results

# 6. 带 token 访问 —— 必须 200
curl -s localhost:5000/api/admin/results -H 'Authorization: Bearer <刚才的token>'

# 7. 汇总
curl -s localhost:5000/api/admin/summary -H 'Authorization: Bearer <token>'
```

**验收**：
1. 7 条命令全部符合预期（特别是第 3 条覆盖、第 5 条 401）
2. `summary` 的返回结构里有 `rounds` 那个数组，且长度是 3
3. 故意提交一个缺 `mode` 的 Session → 400 且 `msg` 是中文
4. 库里 `SELECT COUNT(*)` 和提交过的不同学号数一致
