# 任务书 · 接线：把成绩提交到后端

> 先读 `CONTRACT.md` 的 **6.1**（接口）、**6.1.1**（静态伺服）、**§10 测试汇报的要求**（★ 这一节是新加的，必须遵守）。
> 另外看一眼 `js/submit.js` 的**头部注释**，接口都写在里面。

## 背景：数据链路断了

后端（`server/`）和前端提交层（`js/submit.js`）都做完并验收过了，**但中间没接上**：

```
index.html 里没引 submit.js           ← 压根没加载
没有任何地方调用 Submit.send()        ← 成绩不会发出去
                    ↓
学生玩完一局，教师后台看不到他
```

**这一条不改，总验收测不出真东西。**

## 改四个文件

| 文件 | 改什么 |
|---|---|
| `index.html` | 加一个 `<script>`；再加一个开发期的调试提示 |
| `js/engine.js` | 第 3 轮结束时，组装 Session 并提交 |
| `js/results.js` | 加「导出成绩单」按钮；**并修一句被误删的话** |
| `js/brief.js` | 一颗按钮的文字（它现在在说假话） |

**不碰其他文件。不跑 git。**

## 一、`index.html`：加载 submit.js

在 `js/round.js` 之后（顺序不敏感，但放在引擎那一组里比较整齐）：

```html
<!-- 成绩提交：POST /api/submit，失败静默、不影响游戏 -->
<script src="js/submit.js"></script>
```

## 二、`js/engine.js`：第 3 轮结束时提交

### 在哪一句

你之前加的 `finishRound()` 里，判断"第 3 轮结束"那个分支。
现在的逻辑大概是：

```js
if (roundNo >= 3) { showScreen('results'); return; }
```

**在这个 `showScreen('results')` 之前**，加提交。

### 怎么做

```js
// ★ 只在第 3 轮结束时提交一次，不要在每轮结束时提交
if (typeof Submit !== 'undefined') {
  var session = Scoring.summarizeSession(
    Store.student, Store.mode, Store.rounds, sessionStartedAt
  );
  Submit.save(session);     // 先存 localStorage —— 后端没通时也不丢
  Submit.send(session);     // 发出去就不管了，它内部已经静默处理失败
}
```

### 硬要求

1. **`Scoring.summarizeSession` 的四个参数一个都不能少** ——
   尤其 `startedAt`，不传的话教师后台看到的"用时"恒为 0（契约 5.2 里写明了）。
2. **`Submit.send()` 不要 `await`、不要 `.then`、不要 `.catch`** ——
   它内部已经保证"绝不 reject、不抛错、不弹窗"。你再加一层反而可能引入新的失败路径。
3. **`typeof Submit !== 'undefined'` 这个判断要留着** ——
   万一 `submit.js` 加载失败（网络、路径写错），游戏不能跟着崩。
4. **只提交一次。** 玩家从结果页点「再玩一次」再玩一局，应该**再提交一次**
   （同一个学号会覆盖，后端已经处理了）。但**同一局的第 3 轮结束不能提交两次**。

## 三、`js/results.js`：加导出按钮 + 修一句被误删的话

### ① 加「导出成绩单」按钮

在原来那三个按钮旁边加一个：

```
[ 再玩一次 ]  [ 导出成绩单 ]  [ 进入概念实验室 → ]  [ 回到登录 ]
```

点了之后：

```js
var session = Scoring.summarizeSession(
  Store.student, Store.mode, Store.rounds, /* startedAt 用你手头有的那个 */
);
Submit.exportCsv(session);
```

**为什么要这个按钮**：如果后端部署失败（免费额度会休眠、环境变量配错都有可能），
**学生点一下就能下载一个 CSV 交给老师 —— 这是不依赖运维的退路。**
契约里把它列为"风险对冲"，不是可有可无的东西。

**`Submit` 不存在时，这个按钮应该隐藏**（不是点了没反应）。

### ② ★ 修一句被误删的话

上一次改"话术动态化"的时候，d′ 摆幅 > 0.70 的分支上**整段结论被换掉了**，
连带丢了一句：

> **这就是信号检测论的贡献——把"能不能分清楚"和"敢不敢说有"拆开了。**

**这句和数据变不变没有关系，照样成立。** 当时判定"可以删"是过度了。

**改法**：把这一句加到**大摆幅分支的最后**。大摆幅分支现在长这样：

```
你的 d′ 从 {最小} 涨到 {最大} —— 这不是"代价改变了能力"。
最可能的原因是练习效应：……

不过 c 的变化仍然说明问题：{c 的那段}
```

**在最后补上那一句。** 另外「再注意准确率：…」那句也一起补回来。

**两个分支（小摆幅 / 大摆幅）的最后两句应该是一样的。** 建议抽成一个函数，
两边共用 —— 免得以后又只改一边。

## 四、`js/brief.js`：按钮在说假话

说明页那颗按钮现在写着：

```
开始第一轮 →
```

**但点下去进的是练习轮**（12 位不计分）。**这是句假话。**

改成：

```
开始（先练 12 位）→
```

或者：

```
开始练习 →
```

**你挑一个，并在旁边那行小字里确认已经写了"正式开始前有 12 位练习患者，不计分"**
（上一波加的）。两处要对得上。

## 自测

### A. 后端没起来时（先在终端确认 5055 没服务）

1. 完整玩一局（快速版，约 4 分钟）
2. **游戏全程不卡、不弹窗、控制台没有因为提交失败冒出来的红字**
3. 结果页敲 `Submit.load()` → 应该看到一个完整的 Session 对象
4. **「导出成绩单」点一下 → 下载到一个 CSV，打开看内容完整**

5. 重新玩一局 → 结果页

9. 大摆幅数据下（摆幅 > 0.70），结论块**最后两句在**

## 汇报（★ 按契约 §10 的格式写）

每一项都要写：
**【测什么】【怎么测】【期望】【它怎么失败】【怎么确认它真的会失败】【实测】**

**特别是这几条，必须做"先让它红一次"：**

- **"第 3 轮只提交一次"** —— 怎么验证的？如果它提交了两次会怎样？你怎么知道没有？
- **"后端挂了不影响游戏"** —— 你怎么制造"后端挂了"这个场景的？把 5055 关掉试过吗？
- **"导出 CSV 内容完整"** —— 你怎么判断"完整"的？逐列核过吗？还是只看文件下下来了？

**如果某一条你想不出"怎么让它失败"，直接说"这条我验不了"** ——
比给一个假的绿勾好得多。
