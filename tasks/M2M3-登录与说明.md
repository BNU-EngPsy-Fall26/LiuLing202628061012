## M2：`js/store.js`

**原样实现契约 5.3 节的 `Store` 接口**，一个字段都不多、一个不少。

要求：
- 挂在 `window.Store` 上
- 字段初始值：`student = null`、`mode = null`、`rounds = []`
- `setStudent(id, name)`：name 传 `null` 或空字符串时，视为游客模式
  （即 `student` 存 `{ id: id, name: null }`，`isGuest()` 返回 `true`）
- `setMode(modeKey)`：如果 `modeKey` 不在 `TRIAL_MODES` 里，**抛错**，
  不要默默接受一个错的模式（否则后面算出 NaN 都不知道哪来的）
- `currentMode()`：返回 `TRIAL_MODES[this.mode]`；mode 还没设就返回 `null`
- `pushRound(r)`:追加进 `rounds`；如果已经有 3 个了，抛错
- `reset()`：三个字段恢复初始值

**注释里写清楚**：为什么这些数据必须集中放（契约 5.3 节的"铁律"那段，
简要转述即可）。

## M2：`js/auth.js`

负责 `screen-login` 这一屏。

页面结构（**替换掉现在那段占位内容**）：
```
<h2>登录</h2>
输入框：学号（placeholder「例如 202628061234」）
输入框：姓名（placeholder「你的姓名」）
按钮：开始实验 →        （class="btn btn-primary"）
按钮：暂不登录（游客模式）（class="btn btn-ghost"）
一行提示文字（id="loginMsg"，默认隐藏，出错时才显示，用 --c-danger 上色）
```

行为：
- 「开始实验」：学号和姓名都不能为空（`trim()` 之后判空）。
  为空 → 显示 `loginMsg`「请填写学号和姓名后再开始」，**不要用 alert()**
  （alert 会打断实验流程，而且手机上很难看）。
  都有值 → 调 `Store.setStudent(id, name)`，然后 `showScreen('brief')`
- 「游客模式」：调 `Store.setStudent(null, null)`，然后 `showScreen('brief')`
- 输入框支持按回车直接提交（姓名框上回车 = 点「开始实验」）
- 页面加载时如果 `Store.student` 已经有值（比如从结果页返回），
  把输入框预填上

**注意**：本阶段不做真正的后端登录。`auth.js` 只管把学生信息写进 `Store`，
后端的 `POST /api/login` 是第 5 波的事——**现在不要在代码里留 `fetch` 调用**，
那是以后加的东西，不是现在。

## M3：`js/brief.js`

负责 `screen-brief`（实验说明屏）。这是玩家进来遇到的第一屏**有内容的**页面，
要把三件事讲清楚。

页面结构：
```
<h2>实验说明</h2>

【这一段是核心，要讲清楚三轮结构】
用一个 .card 写：
  你要在急诊分诊台值班三轮，每轮 30 位患者（快速版 16 位）。
  三轮里，你要判断的难度是一样的——
  但每一轮"判错的代价"会变。
  请仔细读每轮开始前的提示。

【选择试次模式】
用 .card 写，两个可选项（用 radio 或两个可点击的卡片都行）：
  ○ 标准版  每轮 30 位患者，全程约 15 分钟。d′ 估计更稳定。（默认选中）
  ○ 快速版  每轮 16 位患者，全程约 9 分钟。课堂时间紧张时用这个。
  → 文案直接读 TRIAL_MODES[mode].desc，不要抄死在 HTML 里

【操作方式】
用 .card 写：
  每轮你会看到一位患者的主诉和生命体征。
  判断他需不需要立即紧急处理 —— 点「立即紧急处理」或「可以等待」。
  你看不到患者的真实情况，只能根据有限的信息判断。
  判断完会立刻告诉你结果，然后进入下一位。

按钮：开始第一轮 →（class="btn btn-primary"）

一行小字（--c-text-dim）：
  本实验只记录你的判断结果，不涉及任何真实医疗场景。
```

行为：
- 两个模式选项切换时，调 `Store.setMode(key)`
- 「开始第一轮」：如果 `Store.mode` 还是 null，先设成 `'standard'`，
  然后 `showScreen('game')`

**注意**：现在游戏引擎（M6）还没做，点「开始第一轮」跳到 game 屏即可，
不用管游戏能不能跑起来。

## 改 index.html 只需要两处

1. 引入两个新脚本，**放在 `js/utils.js` 之后、inline `<script>` 之前**：
   ```html
   <script src="js/store.js"></script>
   <script src="js/auth.js"></script>
   <script src="js/brief.js"></script>
   ```
   （注意顺序：`store.js` 必须在 `auth.js` 和 `brief.js` 前面）

2. `screen-login` 和 `screen-brief` 里现在的占位内容，
   由 `auth.js` / `brief.js` 在加载时**替换掉**（推荐做法：
   在脚本里用 `innerHTML` 重建，或者用 `document.createElement` 拼）。
   **不要去手改 index.html 里那两屏的 DOM**，让 JS 去填。

   如果你觉得 JS 重建 DOM 太绕，**也可以直接改 index.html 里那两屏的 HTML 结构**，
   但必须保持 `id="screen-login"` / `id="screen-brief"` 不变。
