## 一、应用要改哪里（很少）

### ① `server/requirements.txt`：加一行

```
flask
flask-cors
gunicorn
```

**为什么**：Flask 自带的开发服务器**单线程、没加固**，官方明确说不能用于生产。
它每次启动都会打那行 `WARNING: This is a development server…` —— **那行不是废话**。

### ② 项目根目录加一个 `Procfile`

**⚠️ 放在【项目根目录】，不是 `server/` 里。** 内容只有一行：

```
web: gunicorn --chdir server app:app --bind 0.0.0.0:$PORT
```

**逐段解释，写进注释或 README**：

| 片段 | 为什么 |
|---|---|
| `gunicorn` | 生产级 WSGI 服务器 |
| `--chdir server` | 先切到 `server/` 再导入，这样 `app.py` / `db.py` 才找得到 |
| `app:app` | 从 `app.py` 里取那个叫 `app` 的 Flask 实例 |
| `--bind 0.0.0.0:$PORT` | **关键**：`0.0.0.0` 才是"外面能连进来"；`$PORT` 由平台动态分配，**不能写死** |

**★ 为什么 Procfile 放根目录、不放进 `server/`**：

```
如果放进 server/，平台会把「根目录」设成 server/
        ↓
容器里可能【只有 server/ 这一个目录】
        ↓
app.py 里的 ROOT = 上一层目录 → 指向不存在的地方
        ↓
静态文件（index.html / js / styles）全部 404
```

**放根目录 + `--chdir server`，整个仓库都在容器里，静态伺服才找得到文件。**

### ③ `server/app.py`：**不用改**

我核过了，现在是这样的：

```python
if __name__ == '__main__':
    ...
    app.run(host='127.0.0.1', port=PORT, debug=True)
```

**`debug=True` 和 `127.0.0.1` 在这里是【安全的】** ——
这段只在 `python app.py` 时执行，而 gunicorn 是 `import app`，
**根本不跑这段**。所以生产环境里 debug 是关的、host 由 gunicorn 决定。

**别动它。** 本地开发还要靠它。

**（但要在 README 里说明这件事**，免得以后有人看到 `debug=True` 就惊慌。）

### ④ 数据库路径：已经支持环境变量了

DB_PATH = os.environ.get('SDT_DB_PATH') or os.path.join(BASE_DIR, 'sdt.db')

**不用改。** 部署时用 `SDT_DB_PATH` 指到一个**持久磁盘**上（见下）。

## 二、★ 一个必须写进说明的坑：SQLite 的持久化

**容器的文件系统是临时的**：

```
重新部署一次  →  容器重建  →  数据库文件没了  →  全班成绩消失
```

**对作业来说这是致命的**（学生在几天里陆续交，中途重新部署一次全没了）。

**所以必须挂持久磁盘**：

```
平台的「Volume / 持久磁盘」功能
        ↓
挂到 /data
        ↓
环境变量 SDT_DB_PATH=/data/sdt.db
        ↓
数据库落在持久盘上，重新部署也不丢
```

**★ 但要在部署说明里如实写明**：

- 如果**免费档不支持持久磁盘**，那就**别在中途重新部署**
- 或者：**挑一个支持免费持久盘/免费数据库的平台**
- 或者：**只在实验当天部署，收完数据就导出 CSV 备份**

**别假装这个问题不存在。**

## 三、怎么验证部署成功（写进部署说明）

**按顺序验，一发现问题就停下**：

| # | 做什么 | 期望 |
|---|---|---|
| 1 | 打开 `https://你的域名/` | 学生端登录页出来了 |
| 2 | 打开 `https://你的域名/admin.html` | 教师端登录页 |
| 3 | 填对口令进后台 | 进去了（**不是默认口令**） |
| 4 | 玩一局快速版（约 4 分钟） | 能玩完，不卡 |
| 5 | 刷新教师后台 | **你那一行在表格里** |
| 6 | 按 F12 看 Console | 无红字 |
| 7 | **★ 访问 `https://你的域名/server/app.py`** | **404**（后端代码不能被下载） |
| 8 | **★ 访问 `https://你的域名/server/sdt.db`** | **404**（数据库绝不能泄漏） |
| 9 | **★ 访问 `https://你的域名/CONTRACT.md`** | **404** |
| 10 | 等 20 分钟不访问，再打开 | 冷启动能自己醒过来（免费档会休眠） |

**第 7、8、9 条最要紧** —— 线上环境和本地不一样，白名单**必须重新验一遍**。

## 五、自测

### ① 本地用"生产模式"跑一遍 ★ 最重要

**在做任何平台操作之前，先在本地模拟生产环境**：

```bash
cd ~/Documents/工程心理学作业/sdt-lab
pip3 install gunicorn
SDT_ADMIN_PASSWORD=test123 SDT_DB_PATH=/tmp/prod-test.db \
  python3 -m gunicorn --chdir server app:app --bind 0.0.0.0:5056
```

**另开一个终端验**：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5056/          # 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5056/admin.html # 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5056/server/app.py    # 404
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5056/server/sdt.db     # 404
curl -s -X POST http://127.0.0.1:5056/api/admin/login \
  -H 'Content-Type: application/json' -d '{"password":"test123"}'        # ok:true
```

**【★ 怎么确认它真的会失败】** 把 Procfile 里那行改成 `--chdir .`（＝切到根目录），
`app:app` 会导入失败 —— **服务起不来，这几条全红**。说明它们真的在验这件事。

**这一条跑通了，说明应用【本身】是可部署的**，剩下的只是平台配置问题。

### ② Procfile 那一行经得起推敲

**【测什么】** 从"项目根目录"出发，那条命令真能起来（而不是只有 `server/` 里才能起）
**【怎么测】** 上一个测试就是在根目录跑的 —— 顺便确认它没依赖"当前目录恰好是 server"
**【★ 怎么确认它真的会失败】** 去掉 `--chdir server`，必须起不来。

### ③ README 和部署说明有没有漏项

**【测什么】** 照着 `docs/部署步骤.md` 从头念一遍，**每一步都能对应到一个具体动作**
（点哪里、填什么、在哪一页）
**【怎么测】** 逐条检查有没有"打开设置页面"这种含糊说法
