## ① `js/lab/roc.js`：方向词写死了

**位置**：第 374 行附近

```js
' 涨到 ' + (dVals.length ? dVals[dVals.length - 1].toFixed(2) : '—') +
```

**问题**：写死「涨到」。玩家 d′ 从 1.59 掉到 0.00，页面却说"涨到 0.00"。

**`results.js` 第 414 行有正确写法，照抄那套逻辑**：

```js
var dFrom = dVals[0];
var dTo   = dVals[dVals.length - 1];
if (dFrom === dTo) { dFrom = Math.min.apply(null, dVals); dTo = Math.max.apply(null, dVals); }
// 然后用
(dTo >= dFrom ? ' 涨到 ' : ' 掉到 ')
```

**`results.js` 里那段注释解释了为什么要处理"两轮数据相同"的极端情况**（见它第 400-406 行），
**一起照抄过来**，别只抄一半。

**顺便检查 `roc.js` 里 c 的那句**：

```js
var cPath = '你的 c 从 ' + cs[0] + ' 走到 ' + cs[1] + ' 再掉到 ' + cs[2];
```

**这句也写死了「再掉到」。** 如果玩家第三轮的 c 反而更高，它就是假话。
**按同样办法改成动态的**（比较 `cs[2]` 和 `cs[1]`）。

## ② `js/lab/roc.js` + `js/results.js`：解释段落按方向分支

### 问题

两个文件的"大摆幅"分支里都有这一段（文字略有差异）：

> 最可能的原因是**练习效应**：前几轮你还在摸索怎么读生命体征，**后面已经熟练了**。
> 纵向实验里很常见，所以正式实验都会先做一轮练习再开始计分。

**这段话只在 d′ 上升时成立。** d′ 下降时它自相矛盾 ——
一边说"从 1.59 掉到 0.00"，一边说"你越来越熟练"。

### 改法：按 `dTo` 和 `dFrom` 的关系分两种

**d′ 上升**（`dTo > dFrom`）→ 保留现有那段：

> 最可能的原因是**练习效应**：前几轮你还在摸索怎么读生命体征，后面已经熟练了。
> 纵向实验里很常见，所以正式实验都会先做一轮练习再开始计分。

**d′ 下降**（`dTo < dFrom`）→ 换成：

> 最可能的原因是**疲劳或注意力下降** —— 这种实验越到后面越容易判断得草率。
> 也可能是**标准被推到了极端**：打中和误报一起变得很高时，两者的差距反而会缩小，
> d′ 就测不准了。

**★ 两种情况下那两句收尾都不能丢**：

- 「再注意准确率：…」
- 「这就是信号检测论的贡献——把"能不能分清楚"和"敢不敢说有"拆开了。」

（第 1 次修复时这两句丢过一次，这次别再丢。）

### 注意：不是"涨了"而是"不稳"

如果三轮是 `1.5 → 0.3 → 1.6`（有涨有掉），**上面两种说法都不合适**。

**这种情况用第三种**：

> 三轮之间你的 d′ 忽高忽低 —— 这更像**判断本身不稳定**，而不是"能力变了"。
> 每轮只有 15 个信号 + 15 个噪音，抽样波动本来就不小。

**判断规则**：
```
dTo > dFrom 且 单调上升     → 练习效应
dTo < dFrom 且 单调下降     → 疲劳 / 极端标准
其余（有涨有掉）            → 不稳定
```

**"单调"的定义**：三个数依次递增，或依次递减。**别用简单的大小比较**。

### 改法

**① 坐标完全相同的点，横向微微错开**

```js
// 伪码：先按 (x, y) 分组，同一组内的点按 index 横向偏移
```

**③ 悬停提示里注明**
