## ① 分支判据：加"趋势型" ★ 这条最重要

### 问题

你现在用的是**严格单调**：

```
shape = (dUp && dTo > dFrom) ? 'up'
      : (dDown && dTo < dFrom) ? 'down'
      : 'mixed';
```

**真实数据（`1.56 / 1.59 / 0.00`）落到 'mixed'。** 但真相不是"忽高忽低" ——
**是前两轮稳定、第三轮崩了**。

`1.56 → 1.59` 那 0.03 只是抽样噪声，**不该因为它就把整个判断翻过去**。

### 改成四档判据

按这个**顺序**判（先判的优先）：

```
第 1 档：严格单调上升         → 'up'        （练习效应）
第 2 档：严格单调下降         → 'down'      （疲劳 / 极端标准）
第 3 档：★ 趋势型 —— 满足【两个条件】：
           |末轮 − 首轮| ≥ 0.70      （首末差得远）
       且  |次轮 − 首轮| ≤ 0.35      （但中间那轮基本没动）
        → 按【末轮 vs 首轮】的方向判：末轮低 → 'down'，末轮高 → 'up'
第 4 档：其余                 → 'mixed'     （不稳定）
```

**为什么第 3 档要两个条件都满足**：
- 只看"首末差得远" → 会把**真正的忽高忽低**（`1.50 / 0.30 / 1.60`）也判成趋势型
- 只看"中间没动" → 会把 `1.50 / 1.52 / 1.55` 这种**小幅上升**也判进来

**两个一起看，才表示"变化集中在最后一段"。**

### 验证用的三组数据

| 数据 | 期望分支 | 为什么 |
|---|---|---|
| `0.54 / 0.98 / 1.79` | **up** | 严格单调上升（第 1 档） |
| `1.80 / 1.20 / 0.40` | **down** | 严格单调下降（第 2 档） |
| **`1.56 / 1.59 / 0.00`** | **down** ★ | 首末差 1.56 ✓、中间差 0.03 ✓ → 趋势型下降 |
| `1.50 / 0.30 / 1.60` | **mixed** | 首末差只有 0.10 ✗ → 真的在乱跳 |
| `1.50 / 1.52 / 2.50` | **up** | 首末差 1.00 ✓、中间差 0.02 ✓ → 趋势型上升 |
| `1.55 / 1.40 / 1.56` | **（小摆幅，不走这套）** | 摆幅 0.16 < 0.70 |

**★ 两个文件（`results.js` 和 `roc.js`）必须用同一套判据、同一组阈值。**
建议抽成一个共用函数（各自文件里定义一份也行，**但数值必须逐字一致，并加注释说明**）。

## ② c 摆幅很小时，那句话自相矛盾 ★

### 问题

大摆幅分支里现在固定这么起头：

> 不过 **c 的变化仍然说明问题**：你的 c 从 0.00 走到 +0.30 再掉到 +0.20，
> 摆幅 **0.18**（几乎没动）—— **那是你的标准在动**。

**两处矛盾**：

1. 「c 的变化仍然说明问题」—— **c 没动，说明不了什么问题**
2. 「摆幅 0.18（几乎没动）—— 那是你的标准在动」—— **前后打架**

**根因还是同一个**：这段话是照着"c 会动"的样例写的。
**真实情况里，c 不动是完全可能的**（你的那一局 c 摆幅 0.18，几乎没动）。

### 改法：c 那段也按 c 的实际摆幅分两支

**c 摆幅 > 0.20**（真的动了）→ 保持现在的写法：

> 不过 c 的变化仍然说明问题：你的 c 从 A 走到 B 再{C}，摆幅 X（{词}）—— 那是你的标准在动。

**c 摆幅 ≤ 0.20**（几乎没动）→ 换成：

> 不过这一局里 **c 几乎没动** —— 摆幅只有 **X**。
> 说明这几轮的代价变化**没有推动你的标准**：你可能有一套自己固定的判断习惯，
> 不太受"代价变了"这句话的影响。这也是真实存在的情况。

**★ 最后那两句收尾照旧不能丢**（准确率 + SDT 那句）。

### 这条为什么值得改

**它是同一个毛病的第 4 次出现**：

| 次 | 写死的假设 | 被真实数据戳穿 |
|---|---|---|
| 1 | 「几乎没变」 | d′ 摆幅 1.25 |
| 2 | 「涨到」 | d′ 明明在掉 |
| 3 | 「练习效应 = 越来越熟练」 | d′ 在掉 |
| **4** | **「c 的变化仍然说明问题」** | **c 摆幅 0.18** |

**而且"c 没动"本身是个合法结果** —— 它说明这玩家不受代价操纵影响。
**页面该如实说，不该硬套一句"你的标准在动"。**

## ③ `js/lab/dist.js`：同一个东西叫了三个名字 ★

**这一条是玩家反馈的**，不是自查发现的。

### 问题

**同一个概念，在同一个卡片里出现了三种叫法**：

```
卡片标题   噪音与信号两个分布 · 【判定线】切在哪儿      ← 判定线
说明文字   横轴是【判定标准 c】的尺子                 ← 判定标准 c
阴影说明   （【刀】右边、噪音那一片）                 ← 刀
指标小方块 【判定标准 c】 / 【刀的位置】              ← 两个混着用
```

**玩家会以为这是三个不同的东西。**

### 更严重的一层：「刀右边、噪音那一片」**只说了位置，没说意思**

一个不懂 SDT 的人读完这句，**仍然不知道"误报率"到底是什么**。

它告诉你**在哪**，但没告诉你**那意味着什么**。

### 改法

**① 统一用「判定线」。** 那个比喻（"切一刀"）**只在第一次出现时用一次**，
后面全部用「判定线」。

**② 阴影说明改成"说意思"，不只是"说位置"。**

现在的（在第 139~140 行附近）：

```js
'    <span style="color:var(--c-danger);">■ 红色阴影 = 误报率 P(FA)</span>（刀右边、噪音那一片）· ',
'    <span style="color:var(--c-accent);">■ 绿色阴影 = 漏报率 P(M)</span>（刀左边、信号那一片）。',
```

**改成两条独立的说明**（不再用 · 挤在一行）：

```
■ 红色阴影的面积 = 误报率 P(FA)
   判定线【右】侧的噪音 —— 其实没有信号，你却判成了"有"

■ 绿色阴影的面积 = 漏报率 P(M)
   判定线【左】侧的信号 —— 真的有信号，你却判成了"无"
```

**注意三个改动**：

- 「阴影」→「阴影的**面积**」（面积才等于概率，说"阴影=概率"不严谨）
- 「刀右/左边」→「判定线**右/左**侧」
- **补上那半句"你却判成了……"** —— 这是"意思"，不是"位置"

**③ 那张卡片顶部的说明里，把比喻解释一次**

现在是：

```
横轴是判定标准 c 的尺子：噪音分布在 −d′/2、信号分布在 +d′/2，两峰相距 d′。
```

**在前面加一句**：

```
想象你在两条曲线之间切一刀 —— 那一刀就是【判定线】，它的位置由 c 决定。
横轴是判定标准 c 的尺子：噪音分布在 −d′/2、信号分布在 +d′/2，两峰相距 d′。
```

**④ 指标小方块的副标题**

```js
metricBox('判定标准 c', 'lab-dist-v-c', '--c-primary', '刀的位置'),
```

**「刀的位置」改成「判定线在哪」**（或者「不偏不倚 = 0」这种更有信息量的）。

**⑤ 检查 `dist.js` 里其余的「刀」**

```
130:  'c 越大 = 刀越靠右 = 越保守 …'                → 判定线越靠右
171:  metricBox('判定标准 c', …, '刀的位置')          → 见上
```

**代码注释里的「刀」不用改**（那是给看代码的人看的，不是给玩家看的）。
**只改会渲染到页面上的那些字符串。**

**⑥ 顺带看一眼别处**

`js/lab/payoff.js` 和 `js/lab/roc.js` 里有没有同样的混用。
**有就一起统一**，但**不要改动它们的逻辑**。

## ④ 减号统一（小事）

`js/lab/roc.js` 里用的是 **ASCII 连字符 `-`**，`js/results.js` 用的是 **U+2212 `−`**。

**两页显示出来不一样**（`-0.54` vs `−0.54`）。

**统一成 U+2212**（`results.js` 那套是对的）。

**怎么找**：在 `roc.js` 里搜数字格式化那几处（`toFixed` 附近），
把负数的 `-` 换成 `−`。**`results.js` 的 `fmt2` / `fmtC` 有现成写法，照抄。**
