## ★★★ 第一铁律：不许读 hasSignal ★★★

**为什么单独拿出来讲**：如果危重患者的卡片看起来和普通患者不一样
（边框发红、字体加粗、位置不同、有个小图标……），玩家就不用判断了——
一眼就能作弊。**整个实验立刻作废。**

所以：

```
✅ 允许的：根据 vitals 里的数字大小决定颜色（数值偏离越远越红/黄）
❌ 禁止的：任何形式的 if (patient.hasSignal) ...
❌ 禁止的：把 hasSignal 写进 data-* 属性、title、aria-label、id、class
❌ 禁止的：console.log 打印 patient（会把 severity 和 hasSignal 一起打到控制台）
```

**契约 2.4 节说得很清楚**：

> 分档只反映**数值偏离程度**，与"真实是否需要急诊"无关。
> 正常患者也可能有几项偏黄，危重患者也可能各项都正常 ——
> 这正是"信号与噪音分布重叠"的可视化。

**判断标准**：你写的每一个 `if`，如果不看 `hasSignal` 也完全成立，就是对的。

## 卡片结构

### 判断前（`reveal: false`）

```
┌──────────────────────────────────────────────┐
│  P-0423  王先生  54 岁  男                     │   ← 小字，--c-text-dim
├──────────────────────────────────────────────┤
│  主诉                                          │
│  胸痛 2 小时，向左肩放射，伴冷汗                │   ← 字号大一点，一行行读
├──────────────────────────────────────────────┤
│  体温      心率      血压       血氧    意识    │
│  36.9°C    118       96/62      93%     嗜睡    │   ← 等宽字体，分档上色
└──────────────────────────────────────────────┘
```

要求：
- **生命体征一行排开**，每项上面是名称（小字、--c-text-dim），下面是数值
- **数值必须用 `--font-mono` 等宽字体**，并加 `font-variant-numeric: tabular-nums`。
  不然数字宽度不一，每换一个患者整行都会左右跳。
- 血压显示成 `96/62` 的形式（收缩压/舒张压）
- 主诉区**固定最小高度约 3 行**，这样不同长度的主诉不会让后面的体征上下乱跳

### 反馈态（`reveal: true`）

在卡片下方追加一条反馈条，用 `PatientData.feedback[outcome]` 里的文案
（随机抽一条，用 `Utils.pick`），把 `{name}` 替换成 `patient.name`。

配色按 `PatientData.feedbackTone[outcome]` 取，对应：

| tone | 用哪个变量 | 什么情况 |
|---|---|---|
| `normal` | `--c-normal` | H / CR，判对了 |
| `watch` | `--c-watch` | FA，浪费了资源 |
| `danger` | `--c-danger` | M，漏了危重患者 |

反馈条里还要写清楚**真实情况是什么**，用一句话：
- `hasSignal` 是 true 时：「这位患者**确实**需要紧急处理」
- 是 false 时：「这位患者其实**不需要**紧急处理」

> 注意：`reveal: true` 时**允许**读 `hasSignal` —— 因为判断已经做完了，
> 这时候告诉玩家真相是必须的。铁律管的是"判断之前不许泄露"。

## 生命体征分档阈值

按数值判断，**与真实答案无关**。请严格用下面这套：

| 体征 | 正常 `--c-normal` | 需观察 `--c-watch` | 危急 `--c-danger` |
|---|---|---|---|
| 体温 °C | 36.0 ~ 37.5 | 37.5 ~ 38.5 或 35.5 ~ 36.0 | > 38.5 或 < 35.5 |
| 心率 bpm | 60 ~ 100 | 100 ~ 120 或 50 ~ 60 | > 120 或 < 50 |
| 收缩压 mmHg | 90 ~ 140 | 140 ~ 160 或 85 ~ 90 | > 160 或 < 85 |
| 血氧 % | ≥ 95 | 90 ~ 94 | < 90 |
| 意识 | 清醒 | 嗜睡 | 昏睡 / 昏迷 |

用 CSS 类实现：`.vital-normal` / `.vital-watch` / `.vital-danger`
（`main.css` 里已经有这三个类了，直接用）。

**阈值写在文件顶部的一个常量对象里**，方便以后调：
```js
var VITAL_RANGES = { temp: {...}, hr: {...}, ... };
```

## 自测（做完必须自己跑一遍）

M4 可能还没做完（正在并行开发）。**用契约 4.1 的样例 Patient 硬编码自测就行**：

打开 `index.html?dev=1`，F12 控制台粘贴：

```js
// 造一个容器
var box = document.createElement('div');
document.getElementById('screen-game').appendChild(box);

// 用一个"看起来危重"的假患者
PatientCard.render(box, {
  id: 'P-0423', name: '王先生', age: 54, sex: '男',
  chiefComplaint: '胸痛两小时，压榨样，往左肩放射，出了一身冷汗',
  vitals: { temp: 36.9, hr: 128, sbp: 82, dbp: 55, spo2: 88, consciousness: '嗜睡' },
  severity: 1.8, hasSignal: true
}, { reveal: false });

// 再看反馈态
PatientCard.render(box, { /* 同一个患者 */ }, { reveal: true, outcome: 'H' });
```

**要检查的**：
- 心率 128 显示红色，血氧 88 显示红色，血压 82/55 显示红色
- 体温 36.9 显示正常色（绿）
- 数字对齐、不跳动
- 反馈条文案里「王先生」被正确替换

**★ 最后做一次关键自查**：把上面那段代码里 `hasSignal: true` 改成 `false`，
**重新跑一遍，渲染出来必须一模一样**（除了反馈条）。如果不一样，说明你泄露了。
