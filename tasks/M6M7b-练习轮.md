# 任务书 · 练习轮 —— 三轮之前先来 12 位不计分的患者

> 先完整读 `CONTRACT.md` 的 **3.7 节**（练习轮规格）+ 3.8 节（话术规则）+ 3.4 节。

## 为什么要加这个

**这是玩家真玩了一局之后才暴露出来的问题。**

```
第一轮  d′ = 0.54     ← 还在摸索怎么读生命体征
第二轮  d′ = 0.98
第三轮  d′ = 1.79     ← 已经熟练了
```

**这个变化不是"代价"造成的，是练习效应。** 它把实验想证明的东西
（d′ 不变、c 变）直接盖住了 —— 代价的推力（第二轮约 +0.5）
远小于练习带来的变化（+1.25）。

**而且不只是"测不出来"**：结果页会显示「你的 d′ 几乎没变」，
下面三行数字却写着 0.54 / 0.98 / 1.79 —— **页面在说假话。**

## 规格（契约 3.7，逐条照做）

```
说明页 → 练习轮（12 位）→ 「练习结束，正式开始」→ 第一轮 → 第二轮 → 第三轮
```

| 项 | 规定 |
|---|---|
| 位数 | **12 位**（约 90 秒） |
| 组成 | **6 信号 + 6 噪音**，用 `Utils.shuffle` 打乱（和正式轮一样） |
| d′ | **1.5**，和正式轮**完全一致**（否则练习学到的标准对不上正式轮） |
| 反馈 | **和正式轮一模一样** —— 显示真实情况 + `PatientData.feedback` 文案<br>★ **这一条不能省**，反馈才是学习发生的地方 |
| 计分 | **不计分**，**不写进 `Store.rounds`** |
| 界面 | 顶部标注「**练习 · 不计分**」，要显眼但别太抢 |
| 结束时 | 显示一句「练习结束。接下来正式计分，规则和刚才一样。」然后进第一轮 |

**它和正式轮只差两件事**：不计分、有「练习」标注。**其余代码路径应该复用同一套。**

### 建议的实现方式

**不要复制一份试次循环出来。** 把「跑一轮」抽成一个函数，参数化：

```js
runRound({
  roundIndex: 0,        // 0 表示练习轮
  isPractice: true,
  trialsPerRound: 12,
  nSignal: 6,
  nNoise: 6
});
```

正式轮传 `isPractice: false`，其余从 `Store.currentMode()` 读。

**为什么要抽函数**：复制一份的话，以后改反馈逻辑就得改两处 ——
改了一处漏了另一处，练习轮和正式轮的行为会悄悄不一致。**这类 bug 极难查。**

### 练习轮结束后

不要直接进第一轮。中间加一个**停顿**：

```
┌──────────────────────────────────┐
│  练习结束                          │
│                                  │
│  接下来正式计分，规则和刚才一样。     │
│                                  │
│  [ 开始第一轮 → ]                  │
└──────────────────────────────────┘
```

用 `screen-round` 那一屏来显示就行（或者你自己判断哪里合适）——
**关键是要有个停顿**，让玩家知道"从这里开始算数了"。
