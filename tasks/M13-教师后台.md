## ★ 为什么是独立页面

- `index.html` 是**学生**用的。学生翻源码不该看见"有个后台在记录我的数据"
- 教师端**网址本身就是入口** —— 老师存个书签就行，不用做隐藏参数那套
- 两个页面**共用** `js/chart.js`、`js/utils.js`，代码不重复

## 页面结构

### 1. 登录

```
急诊分诊台 · 教师后台

[ 口令输入框 ]  [ 进入 ]

（一行小字）仅供教师使用
```

- 口令 POST 到 `/api/admin/login`，拿到 token
- token 存 `sessionStorage`（关掉标签页就失效）
- 口令错误显示 `--c-danger` 红字，别用 alert
- **★ 口令不许硬编码在前端任何地方**

### 2. 顶部工具栏

```
[全部] [标准版] [快速版]     [刷新数据]     [ 退出登录 ]
```

按 `mode` 过滤，调 `/api/admin/results?mode=xxx`。
「退出登录」清掉 token、回到登录界面。

### 3. 概览卡片（4 个）

从 `/api/admin/summary` 读：

```
提交人数     42          平均 d′     1.42
平均 c       +0.08       平均准确率   74%
```

数字用 `--font-mono` 等宽。

### 4. ★★★ 四张图（这是这一页的核心）

全部用 `Chart.make()`，统一主题。

#### 图 1：三轮的 d′ 与 c —— **最重要的一张**

横轴三轮（第一轮 / 第二轮 / 第三轮），**两条线**：
- **平均 d′**（`--c-accent`，左轴）
- **平均 c**（`--c-watch`，右轴）

数据来自 `summary.rounds`。

**图下面必须配一句话**：

> **全班平均 d′ 几乎不动，而 c 从第 1 轮走到第 3 轮 ——
> 这正是这场实验要证明的：代价改变的是标准，不是能力。**

**这张图是整个作业的教学结论，老师投屏就靠它。**

#### 图 2：班级 ROC 散点图

横轴每个人的 P(FA)、纵轴 P(H)，**一人一个点**。
每个人三个点（三轮各一个）也行，用不同颜色区分轮次。

#### 图 3：d′ 分布直方图

横轴 d′ 分箱，纵轴人数。**画一条竖线标出平均 d′**。

#### 图 4：实测 d′ vs 系统 d′

横轴 `system_dprime`（都是 1.5），纵轴实测 d′，一人一个点，
**再画一条对角线**。

图下一句：

> 理想观察者落在对角线上。真人通常落在对角线**下方** ——
> 因为我们有内部噪声，还有注意力的波动。

（如果实测点都贴着 1.5，说明这个设计里的体征读数相当透明，
那这句话就不成立 —— **照实说**，别硬套。）

### 5. 成绩表格

每人一行，**可点表头排序**，**有搜索框**（按学号或姓名）。

列：学号 · 姓名 · 模式 · 第一轮 d′/c · 第二轮 d′/c · 第三轮 d′/c · 总 d′ · 总 c · 准确率 · 提交时间

- 数字用等宽字体、右对齐
- 超过 10 人时表头 `position: sticky` 吸顶

## 硬约束

- 颜色一律 `var(--c-*)`；配色和 `index.html` 同一套（深色监护仪风）
- **要在 `admin.html` 里引这些**（路径和 index.html 一样）：
  ```html
  <link rel="stylesheet" href="styles/tokens.css">
  <link rel="stylesheet" href="styles/main.css">
  <script src="js/utils.js"></script>
  <script src="js/chart.js"></script>
  <script src="js/vendor/echarts.min.js"></script>
  ```
  （**注意 `chart.js` 依赖 `echarts`，顺序别反**）
- **不需要** config / store / patient / engine 那些 —— 教师端不玩游戏
- 手机上看不清表格没关系（这是投屏用的），但**别横向溢出整个页面**
- `Chart.make()` 是在容器可见时调用的，**不要在隐藏的 div 里建图**

6. 「退出登录」能回到登录界面
7. 控制台无红字
