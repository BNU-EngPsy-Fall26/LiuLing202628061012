## M11 `js/lab/payoff.js` —— 代价与最优判据

### ★ 这个面板是给你那三轮设计配的"理论解释器"

玩家在游戏里被三轮的代价推着走，这一屏告诉他**为什么**。

### 顶部：轮次切换

三个按钮：「第一轮 常规值班」「第二轮 爆满警报」「第三轮 复盘之后」，
默认选中第一轮。**切换时下面所有内容跟着变。**

三轮的支付矩阵**从 `ROUNDS[n-1].payoff` 读，不许写死**。

### 支付矩阵表（可编辑）

```
                   说"有信号"        说"无信号"
实际 有信号      V(H) = [ +10 ]    C(M) = [ −10 ]
     无信号     C(FA) = [ −10 ]    V(CR) = [ +10 ]
```

数字放在 `<input type="number">` 里，**改了就实时重算**下面的量。
初始值从 `ROUNDS[n-1].payoff` 读。

### 先验概率滑块

`P(S)` 从 0.05 到 0.95，步长 0.01，**默认 0.5**（你的设计里三轮都是 0.5）。

### 两个公式（原样显示，不要改）

```
β_opt = [P(N)/P(S)] × [V(CR) − V(FA)] / [V(H) − V(M)]
c_opt = ln(β_opt) / d′          其中 d′ = 1.5（契约 3.4）
```

### 计算结果（四个小方块）

```
P(S)          0.50
P(N)          0.50
最优 β        1.00
最优 c        0.00
```

**★ 自测必须对上契约 3.4 那张表**：

| 轮次 | β_opt | c_opt |
|---|---|---|
| 第一轮 | **1.00** | **+0.00** |
| 第二轮 | **2.25** | **+0.54** |
| 第三轮 | **0.30** | **−0.80** |

**这三个数对不上，整个面板就是错的。**

### 图 `<div class="chart-sm">`

横轴 P(S) 从 0.05 到 0.95，纵轴 **β_opt**，画一条曲线。
在 P(S)=0.5 处画一条竖虚线，标出当前值。

### 底部一段解读（数字动态填）

> 第二轮只改了 C(FA) 和 V(CR)，最优 β 就从 1.00 升到 2.25 ——
> **误收的代价上升，理性的人就该更保守。**
> 第三轮只改了 C(M)，最优 β 掉到 0.30 ——
> **漏报的代价上升，理性的人就该更宽松。**
>
> **三轮里 d′ 一直是 1.5，你的分辨能力没变。变的只有该用什么标准。**

## M12 `js/lab/vigilance.js` —— 警觉衰退模拟

### ★ 这个面板和你的三轮设计是绝配

三轮证明的是 **c 会被代价推动**；这个面板证明的是 **d′ 会被疲劳压低**。

**两个放在一起，d′ 和 c 是两个独立维度这件事才算讲透。**

### 场景设定（写清楚）

> 急诊分诊员值夜班。持续盯着分诊台 **2 小时**会发生什么？
> 模拟 Mackworth 钟实验：**8 个 15 分钟时段，每时段 30 个信号 + 270 个噪音事件。**

### 两个复选框（默认都勾上）

- ☑ **敏感性下降**：d′ 随时间降低（唤醒 / 资源理论）
- ☑ **标准偏移**：c 随时间升高（期望理论）

### 一个按钮：「开始模拟」

**每点一次结果都不一样** —— 因为每个时段是从 SDT 模型**采样**出来的，
不是画一条预设曲线。这一点要在界面上说明。

### 采样规则

每个时段 t（0~7）：

```
d′_t = 1.5 × (1 − 0.06 × t)        // 勾了"敏感性下降"才生效，否则恒为 1.5
c_t  = 0.0 + 0.09 × t              // 勾了"标准偏移"才生效，否则恒为 0

pH_t  = 1 − ncdf(c_t − d′_t/2)
pFA_t = 1 − ncdf(c_t + d′_t/2)

H_t  = Binomial(30, pH_t)          // 30 个信号里击中几个
FA_t = Binomial(270, pFA_t)        // 270 个噪音里误报几个
```

`Binomial(n, p)` 用 n 次 `Utils.rand01(rng)` < p 累加实现。

**然后从 H_t / FA_t 反算**（用契约 4.5 的公式，调 `Utils.zScore`）

**★ 关键**：反算出来的 d′ 和 c **不会**正好等于上面设定的值 ——
因为只有 30 / 270 个试次，有抽样波动。**这正是要展示的东西**：
"你看到的实测值，永远带着噪声。"

### 图 `<div class="chart">`（高 340px）

横轴 8 个时段，两条线：
- **实测 d′**（左轴，`--c-accent`）
- **实测 c**（右轴，`--c-watch`）

**双 Y 轴**。悬停提示显示时段、d′、c、H、FA。

### 图下方：一段解释

> **只勾"敏感性下降"** → d′ 一路走低，c 基本不动
> **只勾"标准偏移"** → c 一路走高，d′ 基本不动
> **都勾上** → 两个一起动
>
> 把两个都关掉，再点几次"开始模拟" —— **你会看到一条上下抖动的水平线。
> 那不是在变化，那是抽样噪声。** 真实实验里这两件事很容易搞混。

### 底部两块小卡片（说明两种机制）

**左：敏感性下降（d′ 降低）**
- 唤醒理论（Welford）：长期没有事件 → 唤醒水平下降 → 两个分布靠拢
- 维持需求理论（Warm）：持续注意消耗认知资源 → 资源耗竭

**右：标准偏移（β 升高）**
- 期望理论（Baker）：漏掉信号 → 主观 P(S) 下降 → 调高 β → 更多漏报 → 恶性循环

**再补一行"阻止技术"**：

> 目标样例 · 降低事件率 · 培训 · 休息 · 结果反馈 · 虚假信号 ·
> 置信水平报告 · 间歇的第二任务
