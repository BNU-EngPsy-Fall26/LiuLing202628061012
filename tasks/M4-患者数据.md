## 要实现的接口（契约 5.1）

```js
window.PatientGen = {
  generate: function (opts) { ... }   // → Patient（结构见契约 4.1）
};
```

`opts` 有三个字段：
- `hasSignal` — boolean，这位患者是否真的需要紧急处理
- `dPrime` — number，本轮的系统设定 d′（从 `Store.currentMode()` 之外单独传入，
  由调用方给，默认用 `D_PRIME`）
- `rng` — 可选，形如 `{ next: function(){ return 0~1 } }`。
  不传时全部随机数走 `Math.random` 兜底。
  **这个参数必须层层透传给 `Utils.randN` / `Utils.pick`**，
  否则将来没法用固定种子复现同一批患者。

## 核心逻辑（★ 这一段是全项目最要紧的代码，请严格按契约来）

### 第一步：采样底层决策变量 severity

```js
// 契约 3.2 节
var severity = hasSignal
  ? Utils.randN(dPrime, 1, rng)   // 真危重：N(d′, 1)
  : Utils.randN(0, 1, rng);       // 其实没事：N(0, 1)
```

**★ 铁律：这两行是全文件唯一允许出现 `hasSignal` 分支的地方。**
从下一行开始，不管 `hasSignal` 是什么，代码路径必须**完全一样**。

### 第二步：从 severity 换算生命体征

严格照契约 3.3 节的公式，**一个都不要改**：

```js
心率   = clamp(round( 72 + severity * 14  + randN(0, 4)), 45, 180)
收缩压 = clamp(round(118 - severity *  8  + randN(0, 5)), 70, 200)
舒张压 = round(收缩压 * 0.63 + randN(0, 3))         // 注意：不 clamp，跟着收缩压走
血氧   = clamp(round( 98 - severity * 3.2 + randN(0, 1)), 70, 100)
体温   = clamp(round1(36.8 + severity * 0.45 + randN(0, 0.2)), 34.5, 41.5)
意识   = severity < -0.5 ? '清醒'
       : severity <  0.5 ? '嗜睡'
       : severity <  1.5 ? '昏睡'
       :                   '昏迷'
```

**注意两个方向相反的指标**：心率随 severity **升高**，血压随 severity **降低**。
这是契约有意设计的（真实的危重生理表现），不要"顺手"统一方向。

### 第三步：抽主诉文案

按 `js/patient-data.js` 里 `PatientData.tierRules` 的规则：

1. 按 `bounds` 定出实际档位（`mild` / `mid` / `severe`）
2. 以 `adjacentChance` 的概率**往相邻档偏一档，方向随机**
   （用 `Utils.clamp` 把下标夹在 `[0, 2]` 之间）
3. 从该档的 `PatientData.complaints[tier]` 里随机抽一句（用 `Utils.pick`）

**★ 必须双向偏移，不许只往一个方向偏。** 原因写在 `patient-data.js` 的
`tierRules` 注释里，请读一遍再动手。

### 第四步：拼出 Patient 对象

严格按契约 4.1 的字段名：

```js
{
  id:              'P-0423',      // 4 位数字，从 1 开始随机
  name:            '王先生',       // 取自 PatientData.surnames + honorifics
  age:             54,            // 18~90
  sex:             '男',
  chiefComplaint:  '胸痛 2 小时…',
  vitals: {
    temp: 36.9, hr: 118, sbp: 96, dbp: 62, spo2: 93, consciousness: '嗜睡'
  },
  severity:        1.34,          // ★ 原始值，保留 2 位小数
  hasSignal:       true
}
```

- `sex` 和 `name` 的称呼要一致：`男的用 PatientData.honorifics.male`，
  女的用 `female`。**先定 sex，再据此拼 name。**
- `age` 和姓名、性别之间**不需要任何相关性**，各自独立随机即可。
- `severity` 和 `hasSignal` 两个字段**必须保留**（M5 和调试要用），
  但**渲染那一层不许碰它们**（那是 M5 的铁律，你只要保证字段在就行）。

```js
// 1. 各生成 200 个信号患者和噪音患者，看体征分布
var sig = [], noi = [];
for (var i = 0; i < 200; i++) {
  sig.push(PatientGen.generate({ hasSignal: true,  dPrime: 1.5 }).vitals.hr);
  noi.push(PatientGen.generate({ hasSignal: false, dPrime: 1.5 }).vitals.hr);
}
console.log('信号组心率均值', Utils.mean(sig).toFixed(1));  // 期望约 93
console.log('噪音组心率均值', Utils.mean(noi).toFixed(1));  // 期望约 72

// 2. 看一位完整患者
console.log(PatientGen.generate({ hasSignal: true, dPrime: 1.5 }));

// 3. ★ 关键检查：抽 2000 次主诉，看三档比例是否合理
var tier = { mild: 0, mid: 0, severe: 0 };
for (var i = 0; i < 2000; i++) {
  var p = PatientGen.generate({ hasSignal: true, dPrime: 1.5 });
  // 用主诉文本反查它在哪一档
  ['mild','mid','severe'].forEach(function (t) {
    if (PatientData.complaints[t].indexOf(p.chiefComplaint) >= 0) tier[t]++;
  });
}
console.log(tier);   // 信号患者（severity 均值 1.5）应该 mid 和 severe 居多
```

**期望结果**：
- 信号组心率均值明显高于噪音组（差 20 左右）
- 信号患者的血压明显低于噪音患者
- 信号患者的主诉以 mid / severe 为主，噪音患者以 mild / mid 为主
- **但两边都有交叉** —— 有些噪音患者心率也很高，有些信号患者心率正常。
  这正是 SDT 要的重叠，**如果你发现两组能完全分开，说明写错了**
